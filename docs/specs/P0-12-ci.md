# P0-12: CI: build, lint, tests, level validation, check scripts, Chapter 0 end to end

> DRAFT until wave 3 and 4 land; the job list below is the intent.

**Goal.** Every push proves what can be proven without a Mac, and the Mac-only checks have one
documented command, so "the board says done" is always backed by a green run somewhere.

**Depends on.** P0-01, P0-05 (for validation), P0-10 (for the browser run)

**Files owned.** `.github/workflows/ci.yml`, `.github/workflows/README.md`, `scripts/check/P0-12.sh`,
`scripts/check/ci-local.sh`.

**Platform decision (binding).** GitHub-hosted runners are Linux amd64; this project pins
`linux/arm64` images and targets Apple Silicon only. Therefore:
- Job `fast` (ubuntu-latest, Node 22, pnpm via corepack): `pnpm install --frozen-lockfile`,
  `pnpm -r build`, `pnpm -r lint`, `pnpm -r test`, `levels:validate` over `levels/`, and every check
  script that declares itself Docker-free by containing the line `# ci: docker-free`.
- Job `mac` (macos-latest, which is Apple Silicon on GitHub): runs only if Docker is available on the
  runner (`docker info` succeeds); otherwise it marks itself skipped with a visible notice. GitHub's
  macOS runners do not ship Docker Desktop, so in practice this job is skipped and the full
  `scripts/check/all.sh` runs on a developer Mac via `scripts/check/ci-local.sh`, which records its
  result and git SHA into `docs/ci-local.log` (committed) so the board has evidence.
- No QEMU emulation of arm64 on Linux runners: it is slow and would prove the wrong platform.

**Work.** Workflow with the two jobs, concurrency cancel-in-progress, pnpm cache; `ci-local.sh` that
runs `all.sh`, prints a summary, appends `date, sha, PASS|FAIL` to `docs/ci-local.log`; the browser run
of Chapter 0 (Playwright, added by P0-10) is wired into `ci-local.sh` only. `scripts/check/P0-12.sh`
validates the workflow with `actionlint` if installed (otherwise `node -e` YAML parse) and runs `ci-local.sh`.

**Acceptance check.** `scripts/check/P0-12.sh` exits 0 on this Mac and the `fast` job is green on GitHub.
