> Facts already confirmed from those handoffs (binding):
> - `leaderboard.top` returns `[{ teamId, points }]` (the key is `points`, matching the baseline); `leaderboard.rank`
>   returns `{ rank, score, around: [{ teamId, score }] }`; `leaderboard.addPoints` returns the new score as a number
>   or `null` for a member that is not on the board (`ZSCORE` first, then `ZINCRBY`); `contest.join` returns strictly
>   `true` or `false`; `ticker.publish` returns the `PUBLISH` reply. Reference shapes live in `app/test/fixtures/`.
> - `POST /app/leaderboards/recompute` with `matchIds` `m-001`..`m-008` gives **40,098** rows (m-001 alone 4,827); the
>   pipelined reference took about 120 ms for the eight.
> - WATCH in this node-redis: after a watched key changed, `multi()...exec()` **throws** a `WatchError` whose `name` is
>   plain `"Error"`, so recognise it with `err.constructor.name === 'WatchError'` (a workspace file cannot import it);
>   nothing in the MULTI ran; `execAsPipeline()` ignores WATCH. A `deps.redis.duplicate()` is closed until the learner
>   calls `await conn.connect()`; the game closes it after the call, so the learner never closes it.
> - The ticker: `GET /app/ticker/:matchId` → `{ matchId, subscribed, received, lastSeq, last, recent, gaps, malformed, instance }`;
>   a message is JSON with an integer `seq`; a gap posts `ticker_gap` with `data: { matchId, instance, expected, got, missed }`;
>   `POST /app/ticker/resubscribe { matchId, pauseMs }` answers after the new subscription is confirmed; `PUBLISH` during
>   the pause returns 0 receivers. The subscriber watches the matches live at boot: m-041 and m-042.
> - `service_scaled` event data is `{ service: "app", instances, previous, ids }`; match it with
>   `match: { service: app, instances: 2 }`. The level's switch is "Run my code in the app" in the Build beat.
> - The harness publishes on the channel itself 300 ms after a `channel_message` check starts (good solutions only);
>   a `.js` that publishes inside the function does not satisfy the check on its own, because the runner call happens
>   before the engine subscribes. Live, the learner's curl during the wait is what passes it. Keep `timeoutMs` long.
> - `PUBSUB NUMSUB`, `PUBSUB CHANNELS` and `FUNCTION LIST` are on the read-only allowlist (`packages/shared/src/levels/commands.ts`).
