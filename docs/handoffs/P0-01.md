## What I did not do
- No `vitest.workspace.ts` (each package runs `vitest run` itself; simpler, no root config).
- No Docker, no network beyond `pnpm install`, no git state changes, no docs/BUILD.md edit.
- No React/DOM test environment (jsdom); the ui test is a plain node-env trivial test.
- Tests are not type-checked by `tsc` (they live in `test/`, outside each tsconfig `include`).
- Did not run `pnpm approve-builds`; see surprises.

## What surprised me
- pnpm 10 skips dependency build scripts by default and warns "Ignored build scripts: esbuild".
  Vite and vitest work anyway (esbuild ships its binary as an optional platform package). If a later
  package needs a postinstall (native module), add `pnpm.onlyBuiltDependencies` to root package.json.
- First draft left `tsconfig.tsbuildinfo` next to each package and in repo root; after deleting `dist/`,
  `tsc -b` then considered the build up to date and emitted nothing. Fixed by `tsBuildInfoFile:
  dist/.tsbuildinfo` in each composite package, so `rm -rf dist` always forces a rebuild and nothing
  stray is left outside gitignored `dist/`. `ui` uses `tsc --noEmit` (not `-b`) for the same reason.
- `pnpm -r` skips the root project, so root scripts calling `pnpm -r build` do not recurse.

## What the next agent must know
- ESM + NodeNext: relative imports in engine/app/runner/shared source need the `.js` extension
  (`import { x } from './x.js'`). `package.json` has `"type": "module"`.
- TypeScript project references: `@quest/shared` is `composite` and builds to `dist/` with `.d.ts`.
  A consumer needs BOTH `"@quest/shared": "workspace:*"` in package.json AND
  `"references": [{ "path": "../packages/shared" }]` in its tsconfig, then builds with `tsc -b`.
  Resolution goes through shared's `exports` (dist), so shared must be built first; `pnpm -r build`
  orders this topologically from the workspace dependency. Consumers must be `composite` too, and
  every composite package needs `rootDir: src`, `outDir: dist`, `tsBuildInfoFile: dist/.tsbuildinfo`.
- Node packages use `"types": ["node"]`; `@types/node` is hoisted from the root.
- ui is NOT composite and does not reference shared yet. If ui needs shared types: add the
  `workspace:*` dependency and import types only (bundler resolution reads shared's `exports.types`
  from dist, so build shared first), or add a reference and drop `noEmit` as needed.
- vitest: each package has `"test": "vitest run"`, tests in `<pkg>/test/*.test.ts`, importing
  `describe/test/expect` explicitly from `vitest` (no globals). Vitest picks up `.ts` directly, so tests
  can import `../src/x.js` without building. Add new tests under `test/`, not `src/`, or they will be
  compiled into `dist` (spec allows node:test elsewhere if a spec names it).
- Lint: `eslint .` per package, resolving the root `eslint.config.js` by walking up. No type-aware
  rules. Add `globals` there if a package needs Node/browser globals beyond `console`/`process`
  (ui code with `document` passes today because `no-undef` is off for TS files in the recommended set).
- Format: `pnpm format` runs prettier over everything including docs and the lockfile; there is no
  `.prettierignore` (not an owned file), so pnpm-lock.yaml and docs may be reformatted. Consider adding one.
- `.gitignore` already covers node_modules, dist.
