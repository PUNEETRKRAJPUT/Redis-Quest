### The trace header (contract for the UI)
Request header `x-quest-trace: 1`. Response header `x-quest-trace`, JSON, printable ASCII, at most 3500 chars:
`{"v":1,"total":12.3,"n":5,"e":[["r","GET k",0.1,0.4,"b",1],...]}`. Row = `[kind r(edis)|d(b), label, startMs
from the start of the request scope, ms, by l(earner)|b(uilt-in), ok 1|0]`. `n` counts every call, `e` is what fit
(oldest first). Who ran is the slot runtime's flag at the moment of the call; the route's own queries and every
baseline count as built-in.

### Where the trace lives
The per-request counting is in `@quest/shared`, which this task does not own. The trace therefore wraps the
already counted deps in the app (`app/src/trace.ts`) and uses the counters themselves to decide what is a command
(a call that moved `counters.redisCommands` is one), so there is no second list of command names and no second
counting mechanism. It is only built when the request carries `x-quest-trace: 1`.
