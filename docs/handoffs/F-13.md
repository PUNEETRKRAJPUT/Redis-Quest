# F-13 handoff: show-me panels for streams, time series, Bloom, Search and ACL; the impact log

## What I did
Five new show-me components (pure views in `ui/src/showme/views.tsx`, pure parsers in `ui/src/showme/parse.ts`, polling
wrappers in `ui/src/showme/index.tsx`), sample data in the `#/showme` gallery, ten levels rewired (only the `show_me:`
block changed), the impact log on "What you built", and the README component table. `scripts/check/F-13.sh` exits 0 (output below).
Nothing staged or committed; `docs/BUILD.md` untouched. No Docker was used, so none of the panels was seen against a live Redis (see "Not verified").

## Components
All commands are on the read-only allowlist; the wrappers poll every 2 s through `POST /api/cli`. An empty state is shown when Redis answers with a
"missing" error (`no such key`, `not found`, `does not exist`, `Unknown index name`, `no such index`); any other error (for example WRONGTYPE) is shown as an error.

| component | keys | commands read | empty state |
|---|---|---|---|
| `stream_groups` | stream names | `XLEN`, `XINFO GROUPS <key>`, `XPENDING <key> <group>` (once per group, pending per consumer) | "no stream yet" (missing key, or length 0 with no group); a stream with no group says "No consumer group yet" |
| `ts_chart` | time series keys | `TS.INFO` (retentionTime, totalSamples, labels), `TS.RANGE <key> - + AGGREGATION avg 60000`, last 60 buckets as an SVG sparkline with the last value printed | "no samples yet" (missing key, or 0 samples and no buckets) |
| `bf_card` | Bloom filter keys | `BF.INFO` (capacity, size, filters, items inserted, expansion), `BF.CARD` | "no filter yet" |
| `ft_card` | index names | `FT.INFO` (num_docs, index_definition prefixes, attribute names and types), `FT.SEARCH <index> * LIMIT 0 3 RETURN 0` | "no index yet" (Unknown index name); an empty index says "No documents indexed yet." |
| `acl_users` | ignored | `ACL LIST`, one row per user, `default` first, rules string beside it | "No ACL users came back." |

Levels wired: ch4-02, 03, 04, 05, 06 `stream_groups ["match:m-041:balls"]`; ch4-14 `bf_card ["bf:usernames"]`; ch4-15 `ft_card ["idx:contest"]`;
ch4-16 and ch4-19 `ts_chart ["ts:requests:GET_app_players_:id_stats"]`; ch5-10 `acl_users []`. As the spec says, ch4-04 no longer lists
`match:m-041:balls:dead` and ch4-16 / 19 no longer list `td:latency` (the new panels need no second key); this drops those two extra panels from What you built.

## The impact log
`What you built` now starts (under the story) with a section "Impact log" (`data-testid="impact-log"`, `ui/src/screens/ImpactLog.tsx`, logic in `ui/src/impact.ts`).
Above the list is one line: "8 chapters, N of 96 levels passed, X XP." (my reading of "one-line chapter summary"; it is one line for the whole game, and each
entry names its chapter). Below, in play order, every passed level whose first passing verdict (`verdict === 'right'`) has numbers in `metrics`, or that has
an `interviewElapsedMs`: title, chapter, then the phrases the portfolio prints (`engine/src/portfolio.ts`, same words and rounding): "p99 4,100 ms to 11 ms",
"Postgres calls per request 1 to 0.02", "Redis commands per request 2", "98.7% of requests made no Postgres call", "1,520 requests per second",
"rebuilt in 12:03". A phrase appears only when the save holds the numbers it needs. Levels without numbers are not listed; with none, the section says "No numbers yet".
Difference from the portfolio: the UI does not know an interview's time limit, so overtime reads "rebuilt in 12:03, over the time limit" instead of "over the 20:00 limit".
`ui/src/types.ts` gained `VerdictMetrics` and `metrics` / `elapsedMs` on the progress verdicts (E-04 fields).

## Other changes you should know about
- `ui/src/redisReply.ts`: a real bug found by the new tests. The engine right-aligns array indexes to the widest one (" 9)", "10)"), and the parser compared the column
  of the first digit, so any nested array of 10+ items (XINFO GROUPS has 12 fields per group, TS.INFO and FT.INFO more) lost items. It now matches a token to its level by
  the start column (left-aligned, as the old tests assumed) or the column of the ")" (right-aligned, as the engine prints). The existing parser tests still pass.
- `ui/src/panels/MetricsPanel.tsx`: `Sparkline` takes an optional `period` (default "seconds") for its screen-reader label; `ts_chart` passes "minutes".
- `ui/src/styles.css`: `.impact-list`.
- Tests: `ui/test/showmeF13.test.tsx` (parsers fed with redis-cli text, each view on sample data and its empty states, the impact log on a sample progress payload including
  an earlier works_but_wrong verdict that must not count, an unpassed level that must not show, and the no-numbers case); `ui/test/showme.test.tsx` now expects 19 ids and renders the new views.

## Not verified
- No panel was run against a live Redis 8 with the real level data (no Docker, per the task). The reply shapes are the documented RESP2 ones, parsed from text laid out the way
  `engine/src/cli.ts` `formatReply` prints it; "missing key" error texts (`ERR no such key`, `TSDB: the key does not exist`, `ERR not found`, `Unknown index name`) are matched
  by a pattern and were not checked against the server here. Not verified: whether `XINFO GROUPS` / `FT.INFO` field names differ on `redis:8` beyond those parsed (`attributes`, with `fields` as a fallback).
- `TS.RANGE - +` reads every sample in retention each poll (the spec's command); fine for the game's one-hour series, not verified for a large one.
- `GET /api/progress` carrying `verdicts[].metrics` was taken from the E-04 handoff and `engine/src/progress.ts`; the UI was not run against an engine.
- `pnpm format:check` passes for the whole tree at the time of the run; the ten level files are not formatted by prettier.
