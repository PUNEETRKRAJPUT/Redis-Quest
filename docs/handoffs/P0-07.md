### Call semantics (`slots.call(scope, name, ...args)` in `runtime.ts`)
- Slot **inactive** -> baseline with the same counted deps; baseline errors are app errors (500 `internal`, no slot header).
- **Active** -> learner module loaded with `loadLearnerModule(WORKSPACE_DIR, file, exportName)` (cached per slot,
  eagerly loaded at activation). Load failure (missing file, syntax error, no default export) -> **baseline**, logged
  once per file version at error level, `x-quest-slots: <name>=baseline-load-error`, `/app/slots` state `load_error`.
- Loaded -> `callLearner(fn, deps, args, { timeoutMs: SLOT_TIMEOUT_MS })` (default 10000). Not ok -> `SlotError`.
- One `createLearnerDeps` context **per request** (shared client + pool passed in, so no connection per request);
  every slot and every direct `deps.db.query` in that request add to the same counters. `ctx.close()` after the response
  closes only learner-made `duplicate()`s.
- Every response that touched a slot carries `x-quest-slots: name=baseline|learner|baseline-load-error[, ...]`.
- Files are watched with chokidar `usePolling` every 1 s (all registry files, active or not; non-existent paths work,
  verified). add/change/unlink invalidates the slot's cache; an active slot reloads immediately.

### Adding a slot (rules for level authors)
1. Name it `area.verbNoun` (must match `SLOT_NAME` in `@quest/shared`), unique.
2. Pick the file: `chN/kebab-name.js`, relative, one default-exported function per file (use `exportName` only if two
   slots must share a file; `file#export` must be unique).
3. Write the baseline in `app/src/slots/baselines.ts` with **exactly the learner's signature** `(deps, ...args)`, using
   only `deps.db` / `deps.redis` (so it is counted). Make it the slow or naive path on purpose and say why in a comment.
4. Add the entry to `SLOTS` with `signature` written like `(deps, playerId)` and `returns` (one line, the contract).
5. Call it from a route in `app/src/routes.ts` with `slots.call(scopeOf(req), 'name', ...args)`. Validate inputs in the
   route, not the slot. If the return value has a shape the route depends on, check it and throw
   `slots.contractError(name, 'must return ...')` so a wrong learner return is a 500 with `x-quest-slot-error`, not a crash.
   Expected outcomes (400/404/409) are `throw new HttpError(status, code)`.
6. `pnpm --filter @quest/app test` (the registry test fails on rule breaks; the app also refuses to boot), and update the
   table above. The level YAML names the slot; the engine activates it via `PUT /api/slots`.

## Config pull (as implemented, `engine.ts` `ConfigPoller`)
- `GET ${ENGINE_URL}/internal/app-config` every `APP_CONFIG_POLL_MS` (default 2000), first pull at boot, no overlapping
  pulls, 3 s request timeout. Sends `If-None-Match` with the exact `ETag` header value last applied.
- 304 -> nothing. 200 -> validate `{ target: { redisUrl: redis(s)://... }, activeSlots: string[], dbExtraLatencyMs >= 0 }`
  (latency clamped to 5000), then apply in this order: latency, slots (`setActive`, unknown names warned once and
  ignored), Redis target (`switchTo`, only when the URL changed). The ETag is stored only after apply succeeds.
- Engine unreachable / non-200 / bad body -> keep the last applied config; one warn line on the up->down transition, one
  info line on recovery. Before the first successful pull: `REDIS_URL` from env, no active slots, latency 0.
- `/app/health` exposes `configEtag` (quoted, as served) and `engine: up|down|unconfigured`.
- Target switch: new shared client + new reserved duplicate are created and swapped in immediately; the old pair is
  closed with `close()` (drains in-flight replies), destroyed after 2 s. Clients use `disableOfflineQueue: true`
  (digest: "offline queue may replay non-idempotent commands after reconnect"), `connectTimeout 3000`, reconnect
  backoff `min(100*2^n, 2000)` ms forever, throttled `error` logging. Connect is not awaited: the app boots and
  serves baselines with Redis down.

## Metrics push (as implemented, `MetricsPusher`)
- Every `APP_METRICS_PUSH_MS` (default 1000) **on wall-clock boundaries** (the engine buckets by floor(at/1000) and
  overwrites same-second samples, so unaligned windows would clobber each other), POST `${ENGINE_URL}/internal/metrics`:
```json
{ "instance": "<hostname>", "instanceId": "<hostname>", "at": 1793500000000, "windowMs": 1000,
  "configEtag": "\"f5f6808e747c1c22\"", "activeSlots": ["cache.getPlayerStats"],
  "routes": { "GET /app/players/:id/stats": { "count": 3, "errors": 1, "p50Ms": 2.81, "p99Ms": 251.3,
     "dbQueries": 1, "redisCommands": 5, "noDbCount": 2, "slotErrors": 1 } } }
```
- `instance` is the spec name, `instanceId` the name the P0-06 engine validates; both sent. `at` = window start, epoch ms.
- Route key = `METHOD routerPath`. `errors` = status >= 500 (404 player_not_found is not an error). `p50Ms/p99Ms`
  nearest-rank via `percentile`, ms from Fastify `reply.elapsedTime`, 3 decimals. `dbQueries`/`redisCommands` = sums of
  the per-request counters (P0-08 counting rules). Additive: `noDbCount` (requests with zero DB queries; for a cache
  route, the hits: hit ratio = noDbCount/count), `slotErrors` (responses with `x-quest-slot-error`).
- `/app/health`, `/app/slots`, `/app/metrics` are operational and never counted. Empty windows are pushed with
  `routes: {}` as a heartbeat (so the engine's `instances` list shows idle instances). A failed push drops that window.
- `GET /app/metrics` (per instance): `{ instance, since, totals: { [route]: { count, errors, dbQueries, redisCommands,
  noDbCount, slotErrors } }, lastWindow }`.

## How a learner error and a timeout surface
- Throw (sync or async), timeout, or contract violation -> HTTP **500**, header `x-quest-slot-error: <message>`
  (one line, ASCII, max 300 chars), body `{ error: 'slot_error', slot, name, message }` where `name` is the JS error name
  (`Error`, `TypeError`, `TimeoutError`, `SlotContractError`). Timeout message: `call exceeded 10000 ms`.
- Logged synchronously to `${LOG_DIR}/app/app.log` at level 50: msg `learner code in slot <slot> failed: <name>: <message>`,
  fields `slot`, `route`, `err { name, message, stack }`. `deps.log(...)` lines go to the same file at info with `learner: true`.
- `unhandledRejection` / `uncaughtException` handlers log and keep running. A timed-out call is abandoned, not killed;
  its later Redis/DB calls still run.
- **Synchronous infinite loop**: cannot be interrupted in-process (P0-08's warning holds). The request hangs and the
  instance is frozen until restarted. A worker-thread watchdog notices the stalled heartbeat after `SLOT_TIMEOUT_MS`
  and appends `{"level":50,...,"suspectSlot":"cache.getPlayerStats","msg":"event loop blocked: ..."}` to app.log and
  stderr (tested). After a restart, the same file loops again on first call until the learner fixes it.

## Design decisions to review
1. **In-process learner code, with a watchdog instead of isolation.** Slots run in the app process (fast enough for the
   traffic lessons; the runner forks per call). A sync infinite loop freezes the instance; the watchdog only reports it.
   Mitigation for P0-09: run the level's `behavior` verifier on the runner (which SIGKILLs loops) **before** activating
   the slot in the app, and only activate after a run without `KilledError`.
2. **One counted deps context per request, baselines get the same deps.** Baseline and learner have identical
   signatures and are measured identically, so dbQueries/redisCommands/noDbCount compare baseline vs learner fairly.
   An empty object from a cache slot (`HGETALL` on a missing key) is treated as "not found" (404/401).
3. **`maxRequestsPerSocket: 1` by default (`APP_MAX_REQUESTS_PER_SOCKET`).** Each response closes the Caddy->app
   connection so Caddy redials and Docker DNS spreads requests across instances; without it the Chapter 3 "sessions in a
   Map break at scale=2" lesson would be invisible to a single browser. Cost: one TCP connect + DNS lookup per request
   inside the Docker network. Better fix (P0-02 owner): Caddy `dynamic a app 4000` upstreams with `lb_policy round_robin`,
   then set the env to 0.
4. Spec deviation in register (flagged): learner override **replaces** the baseline, so a learner's `registerUser`
   does not insert into Postgres unless it does so itself. Level 1.16 grades Redis side effects only, so this is fine
   for now; if a later level needs both, call the Postgres insert in the route and make the slot Redis-only.

## What P0-09 (verifier) must know
- Slot -> file mapping for `behavior` runs: `GET ${APP_URL}/slots` (`/app/slots` through the proxy) lists every slot with
  `file`, `exportName`, `signature`, `returns`, `active`, `state`. The runner's `module` is that `file`.
- After `PUT /api/slots`, wait until **every** instance has applied the config: compare each push's `configEtag` (or
  `/app/health` `configEtag`) with the engine's current etag. Allow up to 2 s poll + module load. Don't grade traffic
  before that. Learner slots load eagerly on activation; `state: loaded` in `/app/slots` means ready.
- Baseline runs = `PUT /api/slots { active: [] }`, wait for convergence, run the scenario.
- `x-quest-slots` on any response tells which path served it; `x-quest-slot-error` marks learner failures (count them as
  learner errors, not app errors). `slotErrors` per route in pushes.
- Hit ratio for cache levels: `noDbCount / count` on the route (requires the engine aggregate fix above).
- `ratelimit.allow` baseline is 10 per 60 s per `x-user-id` per instance.
- `SLOT_TIMEOUT_MS` default 10 s; a hanging learner call costs 10 s of a traffic run per request. Consider setting a
  lower value via compose env for traffic levels (needs a compose edit by its owner; the app reads the env).

## What content authors must know
- Learner modules: `export default async function (deps, ...args)`, `deps = { redis, db, log }`. Never connect or close
  clients (no-ops). Use your own key prefix, never `game:*`. Return JSON-safe values; `undefined` becomes `null`.
- A cached `player_stats` row from `HGETALL` comes back with every value as a string (`matches_played: "8"`, `economy: ""`
  for null) while the baseline gives `null` for null columns. Compare fields loosely in assertions.
- `HGETALL` of a missing key returns `{}`; the stats route treats `{}` as not found (404). Negative caching (level 2.5)
  should store a sentinel and return `null`.
- WATCH/MULTI optimistic locking on the shared client is unsafe across concurrent requests (digest: use
  `createClientPool`); not provided yet. Blocking commands (BLPOP, XREAD BLOCK) must use `redis.duplicate()`.
- Editing a slot file takes effect within ~1 s, no restart. A syntax error silently falls back to the baseline (visible in
  app.log and `/app/slots`), it does not 500.
