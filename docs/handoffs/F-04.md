# F-04 (+F-09) handoff: the ideal-way panel and insightUrl in /health

## What I built
- Engine (`engine/src/server.ts`, health route only): `GET /health` now returns `insightUrl: "http://<request host, port stripped>:<INSIGHT_PORT>"` (default 5540, host falls back to `localhost` if the Host header is missing or odd). `docker-compose.yml` already passed `INSIGHT_PORT` into the engine environment (line 56), so it is untouched.
- UI: `ui/src/level/IdealWay.tsx` rewritten; new `ui/src/level/diff.ts` (+ `ui/test/diff.test.ts`); `ui/src/screens/Level.tsx` wiring; `types.ts` (exact `Ideal` / `IdealResponse` shapes from P0-09), `api.ts` (`api.ideal`), `MonacoEditor.tsx` (optional `readOnly`, `height`), `styles.css`. The Insight link needed no change: it already prefers `health.insightUrl`.
- e2e (`ui/e2e/chapter0.e2e.ts`) and `scripts/check/F-04.sh` (derived from F-UI.sh).

## Locked vs shown
`allowed = passed || progress.attempts >= 3 || failed verdicts >= 3`. Allowed: the panel uses `ideal` from the last verify response, else (page reload) fetches `GET /api/levels/:id/ideal` itself. Not allowed: it shows the engine's locked wording ("Not passed yet, and N of 3 attempts used. You can still reveal it.", built client-side to avoid a fetch, which would record `idealRevealedAt`) and a "Reveal anyway" button (`data-testid="ideal-request"`) that calls the GET endpoint, then shows the panel with a "Revealed early" note and flips the stage chip to unlocked.

## What the panel shows
- cli/ops: reference file as a highlighted block (existing hljs `.redis`/`.sh`), each wrong solution in a collapsible `<details>` with its `because` and its code, the engine's `reasoning` text, the learner's beat-3 guess and the task.
- code: reference in a lazy read-only Monaco, and a line diff of the learner's workspace file against the reference. The learner file is found from the task text (`workspace/<path>.js`), read with `GET /api/workspace/file`.
- decision: correct options (labels from the quiz verifier / brainstorm options), per-quiz explanation, wrong options collapsible with `because`.

## Diff view approach
`lineDiff(mine, ref)`: line-level LCS table (files are tens of lines), rows `same | add | del`, rendered in a `<pre>` with green (+ only in reference) and red (- only in learner file) backgrounds, no new dependency.

## Not done / not verified
- The code-mode path (read-only Monaco + diff against the workspace file) is not covered by the e2e, because Chapter 0 has no code levels; the diff algorithm has vitest unit tests, the Monaco and file-read path were only type-checked and built. Files not in the spec's list that I did not touch: no engine unit test was added for the health helper (it is checked by the script with curl through the proxy, and with a `Host: localhost:3300` header).
- Wrong-solution `.js` files are shown as highlighted blocks, not in Monaco.

## e2e (Chapter 0, one run)
Level 1: locked -> pass -> panel shows reference (`./scripts/start`), wrong solutions, "Why the others fall short". Level 3: panel locked with "0 of 3 attempts used"; three wrong answers (verdict `wrong` each) -> panel unlocked with reference and the `WRONGTYPE` wrong solution. Level 4: locked, "Reveal anyway" shows the panel while the level stays unpassed. Insight link on "What you built" is `http://127.0.0.1:5543`.
