## The draw (`engine/src/pool.ts`, `server.ts` start route)
At `POST /api/levels/:id/start` of a pool level with no valid draw: candidates = pool entries minus `rebuild_of`s already in other levels' `drawn`
(all entries if none remain); index = `sha256("<player.id>:<level id>")` first 4 bytes big-endian, modulo candidates.length (pool order).
Stored as `drawn` on the progress entry; first start wins (restarts, re-starts keep it). Blank start (once, when `blanked` is undefined): for each slot
file of the drawn level (`levelSlots` through `SLOT_FILES`) that exists and is non-empty: move to `<file>.before-<pool level id>` (`-2`, `-3`; hard link
then unlink, never overwrites), write an empty file; a missing file is created empty. Recorded as `blanked: [{file, backup}]`. `blank_start: true` on a
`rebuild_of` level blanks the rebuilt level's slot files the same way. The drawn level's `setup` also runs at start.

## Level payload for a pool level (`GET /api/levels/:id`)
`title/story/brainstorm/reward` and `hints` (pool's first, then the drawn level's) from the pool level; `task, showMe, docs, scenario, minRedisVersion`
from the drawn level; `verifiers` = drawn public verifiers then the entry's questions (indices continue); `teach: ""`; `slots` from the drawn level.
`interview` = existing F-12 fields plus `pool: boolean`, `drawn: {id, title, chapter (id), chapterTitle} | null`, `blanked: [{file, backup}]`,
`questionsFrom: number | null` (index of the first follow-up), and `rebuildOf` = the drawn level (`null` before the draw). Before the first start:
`drawn: null`, `task: "The interviewer picks when you start."`, `verifiers: []`. Ordinary and rebuild_of levels get `pool: false, drawn: null, blanked: [], questionsFrom: null`.
`start` response adds `drawn` (id) and `blanked` on pool levels. `verify` grades a synthetic level: the drawn level (its directory, fixtures, slots, scenario, template context)
with the entry's quizzes appended, under the pool level's id; `409 not_drawn` if nothing was drawn (dev-complete without start). `GET .../ideal` and the verify `ideal` are the drawn level's.

## Progress fields added (additive)
`levels[id].drawn?: string`, `levels[id].blanked?: {file, backup}[]`; verdict records gain `metrics?: {p99Ms, baselineP99Ms, dbPerRequest, baselineDbPerRequest,
redisPerRequest, hitRatio, rps}` (only the numbers the traffic check produced; `redisPerRequest` = redis commands / requests; rounded to 4 decimals) and `elapsedMs?` (interview levels: ms into the clock at the verify request).

## Portfolio
`GET /api/portfolio` -> `{ markdown, stats }`; `POST /api/portfolio/write` -> writes `workspace/PORTFOLIO.md`, answers `{ path: "workspace/PORTFOLIO.md", file, bytes, levels (all levels in the game), passed }`
and emits `level.event custom portfolio_written { bytes, levels, passed }`. Numbers come from the metrics of the first `right` verdict of a passed level; a pass without a verdict (dev shortcut) has a line and no number.
Learner text (name, brainstorm line) is markdown-escaped. Workspace list excludes `.before-` backups, `_bundle-*` shims and `PORTFOLIO.md`; empty files show as "(empty)".
UI: `ui/src/screens/Story.tsx` on "What you built": button `data-testid="write-portfolio"`, then the written file rendered with the existing Markdown component and its path. Pool levels show a "The interviewer picked ... your earlier file is at ..." notice (`DrawnNotice`) and a heading before the follow-up questions.

## Harness rules (`scripts/grade/grade.mjs`, `docs/grading.md`)
- Pool level: `ensureUnlocked`, `start` (draws), `GET /api/levels/:id`, take `interview.drawn.id`, find that level (chapters asked for, then everything under `--levels`), play **its** solutions (paths from its directory; bundle/slot/event rules unchanged), `start` again before each solution, answers = drawn level's plus the entry's questions at indices after them (all right for right/works_but_wrong; first one wrong for wrong), verify on the pool level. Row `LEVEL` = pool level, note = `drew <id> (<title>), N follow-up questions`.
- `portfolio_written`: for good solutions the harness POSTs `/api/portfolio/write` after the solution ran and before verify; the engine emits the event.
- `levels:validate` accepts pool levels and rejects: pool entry not earlier / missing, pool level with verify or solutions, rebuild_of together with pool.
