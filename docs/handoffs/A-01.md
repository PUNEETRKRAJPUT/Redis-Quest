# A-01 handoff: app plumbing for Chapter 2 (levels 2.7, 2.8, 2.10) and 429 counting

## What I did
- **Outbox drainer** `app/src/workers/outbox.ts`: every instance polls `outbox WHERE published_at IS NULL` once a second,
  `SELECT ... ORDER BY id LIMIT 100 FOR UPDATE SKIP LOCKED`, `XADD legacydb:changes MAXLEN ~ 10000 *`, then
  `UPDATE outbox SET published_at = now()` and COMMIT in one transaction (a crash between XADD and COMMIT re-publishes:
  at-least-once). Runs while slot `prefetch.applyChange` is active or env `APP_OUTBOX_ALWAYS=1`. One info log line per batch.
  Uses the app's raw pool (no injected DB latency) and the shared Redis client with a 3 s AbortSignal per XADD.
- **Change consumer** `app/src/workers/changes.ts`: per instance, own duplicate-style connection, `XREAD BLOCK 1000 COUNT 100`
  from the stream tail, calls `prefetch.applyChange` per entry while the slot is active. Entries added while the slot is
  inactive are skipped; each activation starts at the tail. Not read from literal `$` on every call (that loses entries added
  between two reads): the tail id is pinned with `XREVRANGE + - COUNT 1` once per activation, then `lastId` advances.
- **Prefetch slots**, **session slots**, routes, **fail-fast learner client** and **`denied`** metric: see the sections below.
- Tests: `app/test/failfast.test.ts` (3), registry and recorder tests updated; app suite is 37 tests. Fixtures
  `app/test/fixtures/prefetch-apply.js`, `prefetch-bulk.js` (reference learner solutions for 2.7).
- Not touched: engine, runner, ui, levels, scenarios, docker files, postgres. `APP_OUTBOX_ALWAYS` reaches the container through a
  compose override file the check writes (`-f docker-compose.yml -f override.yml`); `docker-compose.yml` is unchanged.

## New slots (added to the P0-07 table; the rest of that table is unchanged)
| name | file (under WORKSPACE_DIR) | signature | must return | baseline |
|---|---|---|---|---|
| `prefetch.bulkLoad` | `ch2/prefetch-bulk.js` | `(deps, rows)` | ignored | nothing (returns null) |
| `prefetch.applyChange` | `ch2/prefetch-apply.js` | `(deps, event)` | ignored | nothing (returns null) |
| `session.destroy` | `ch3/session-destroy.js` | `(deps, sid)` | ignored (echoed as `result`); the session must be gone | `Map.delete`, returns `{ destroyed: boolean }` |
| `session.destroyAll` | `ch3/session-destroy-all.js` | `(deps, userId)` | anything (echoed as `result`); every session of the user gone | linear scan of the in-process `Map`, returns `{ destroyed: n }` |

Existing and unchanged: `prefetch.getFixtures (deps)` (baseline reads Postgres), `session.create (deps, user)`, `session.get (deps, sid)`.
The two session files live under `ch3/` to match `session.create/get` as built in P0-07 (the registry path rule is `chN/name.js`).

- `rows` for `prefetch.bulkLoad`: every `matches` row joined with team names, ordered by id (60 rows in the seed), objects
  `{ id, season (number), home_team_id, away_team_id, home_team_name, away_team_name, venue, starts_at (ISO string, UTC, ms), status }`.
  Values are numbers/strings, none null in the seed; `HSET` accepts them as is.
- `event` for `prefetch.applyChange`: `{ aggregate, aggregateId, op, payload }`: `aggregate` is the table name
  (`players`, `teams`, `matches`, `contests`), `op` is `insert|update|delete`, `payload` is the **parsed** row (full new row, old row on
  delete; `starts_at` is the trigger's `to_jsonb` ISO string with offset, numerics are JSON numbers, nulls are real `null`). The slot is called
  for every aggregate, not only matches: the learner filters. Updates that change nothing still emit an event.
- When `bulkLoad` runs: once per instance when it turns active in the engine config (waits up to 5 s for Redis to be ready), and on every
  `POST /app/prefetch/reload` (200 `{ ok, rows, result }`; inactive slot = baseline no-op, so `rows` is still the count). Editing the learner
  file later does not re-run it. With `--scale app=2` it runs on both instances (idempotent for DEL+HSET).

## Routes added
- `POST /app/prefetch/reload` (above).
- `POST /app/logout`: needs the `sid` cookie (401 `not_logged_in` without), calls `session.destroy`, responds `{ ok, result }` and
  `Set-Cookie: sid=; Path=/app; HttpOnly; SameSite=Lax; Max-Age=0`.
- `POST /app/logout-all { userId }`: 400 `invalid_user_id` without a string userId, calls `session.destroyAll`, responds `{ ok, userId, result }`.

## The stream entry format (`legacydb:changes`)
`XADD legacydb:changes MAXLEN ~ 10000 * aggregate <table> aggregate_id <id> op <insert|update|delete> payload <json>`, e.g.
`1793505443153-0  aggregate players  aggregate_id p-001  op update  payload {"id":"p-001","age":20,"fame":30,"name":"Jignesh Rathod",...}`.
All four values are strings; `payload` is `JSON.stringify` of the outbox jsonb. Plain stream, no consumer group (each instance `XREAD`s
the tail, so each sees every entry; the digest says plain XREAD has no PEL and no ack, fine for a cache that a reload repairs).

## Fail-fast learner Redis client (`packages/shared/src/learner`)
- `deps.ts`: the client `createLearnerDeps` creates itself now has `disableOfflineQueue: true` (the app's own shared client already had it from
  P0-07). New option `commandTimeoutMs`, default env `LEARNER_REDIS_COMMAND_TIMEOUT_MS`, then **2000**; 0 turns it off.
- `failfast.ts` (new, exported from `@quest/shared`): `failFast(client, ms)` is the outermost wrapper over the counting proxy. Every command goes
  through `client.withAbortSignal(signal)` (so the timer cancels a still-queued command) and is raced against the timer; counting is unchanged
  (one command = one count). Exempt from the timeout: listener/lifecycle methods, subscribe family, `multi()` itself (its `exec` and
  `execAsPipeline` are timed), blocking reads (`blPop`, `brPop`, `bzPop*`, `xRead`, `xReadGroup`, ...), scan iterators. `duplicate()` clones stay wrapped.
- **Error the learner sees** (also in the 500 body `{ error: 'slot_error', slot, name, message }` and header `x-quest-slot-error`):
  - Redis stopped (`docker compose stop redis`, client not ready): `name: "Error"`, `message: "The client is offline"`
    (node-redis `ClientOfflineError`; this build reports `name` as plain `Error`, so teach `catch (err)` on the message or just catch-all). Rejects in about 10 ms.
  - Redis paused or hung (socket open, no reply): `name: "RedisCommandTimeoutError"`,
    `message: "Redis command hGetAll got no reply within 2000 ms (is Redis down?)"`. Rejects at 2.0 s.
  A learner that catches and falls back to Postgres therefore serves normally in both cases. The app's baseline paths never touch Redis, so they
  keep answering with Redis down (checked: `/app/players/p-001`, `/app/fixtures` -> 200).
- Side effect: the runner (also `createLearnerDeps`) gets the same 2 s command timeout. Not verified: runner behaviour under a hung Redis; the runner tests were not re-run (not owned).

## The 429 metric field
Per-route `denied` (count of responses with status 429), additive next to `slotErrors`. In the push body
`routes["GET /app/limits/ping"] = { count, errors, p50Ms, p99Ms, dbQueries, redisCommands, noDbCount, slotErrors, denied }`, and in `GET /app/metrics` totals.
429 is not counted in `errors` (only >= 500 is). The engine ignores the field today (its `/api/metrics` aggregate still keeps count/errors/p50Ms/p99Ms);
F-11 (limiter panel) needs the engine aggregate to sum `denied` like the P0-07 note asks for `redisCommands`. Real example from the check:
`{"count":14,"errors":0,"p50Ms":0.403,"p99Ms":0.741,"dbQueries":0,"redisCommands":0,"noDbCount":14,"slotErrors":0,"denied":4}`.

## What I did not do / surprises
- Timing margin: the applyChange assertion is 2 s and the pipeline is poll (up to 1 s) plus XREAD; measured about 0.9 s. A loaded Mac could flirt with it.
- `pnpm format` at the repo root rewrites every file, including other agents' in-flight ones; I ran `prettier --write` on `app/` and `packages/shared/src/learner/` only
  (one early repo-wide run happened before I noticed; the only files it could have touched outside my paths are the unformatted in-flight levels files, formatting only).
- The consumer does not use consumer groups, so a restart loses events that arrive while the instance is down; level 2.7 repairs with `POST /app/prefetch/reload`.
- Not verified against official docs: node-redis `xRead` return shape under RESP2 is what the loop relies on (it works in the check); abort of an already-written command is not
  verified, which is why the timeout is also a race.
- `workspace/` is a bind mount, so the check's learner files appear on the host for the few minutes it runs.
