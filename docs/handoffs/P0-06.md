# P0-06 handoff: engine skeleton

## What I did
- `engine/` is now the single-instance game server (Fastify 5, `@fastify/websocket`, `@fastify/static`, pino, node-redis v5). Modules in `engine/src/`: `config`, `log`, `events` (WS fan-out plus 200-event ring), `progress` (file store), `mirror` (Redis `game:*`), `redis` (connection manager), `cli` (shell split + redis-cli formatting), `levels`, `setup`, `verify` (the one function P0-09 replaces), `workspace`, `metrics`, `appconfig`, `logtail`, `server` (all routes), `main`.
- Dependencies added to `engine/package.json`: `fastify`, `@fastify/websocket`, `@fastify/static`, `pino`, `redis` (lockfile changed). No `pg`: the `/health` Postgres probe is a TCP connect to the host and port in `DATABASE_URL`.
- `docker-compose.yml`: marker block `# --- P0-06 engine mounts start/end` inside the `engine` service. The markers did not exist; I created them and moved the engine's existing `environment:` line into the block (a duplicate key is not allowed). Block adds `LEVELS_DIR=/levels`, `ENGINE_DEV`, the four host ports (`REDIS_PORT`, `PROXY_PORT`, `INSIGHT_PORT`, `PG_PORT`, exposed so levels can use `{{env.NAME}}`), and the volumes (`workspace`, `logs`, `.progress`, `./levels:/levels:ro`). The workspace, progress and levels host paths read `QUEST_WORKSPACE_DIR`, `QUEST_PROGRESS_DIR`, `QUEST_LEVELS_DIR` (default to the real ones) so the check can use scratch dirs.
- vitest in `engine/test/` (35 tests): progress atomicity, serialised updates, restore, reconcile; CLI split and formatting; workspace containment incl. symlink escape; app-config ETag; metrics store; event ring. The P0-01 placeholder test was deleted.
- `scripts/check/P0-06.sh` (bash 3.2). Needs no host port: engine publishes none, so HTTP and WebSocket are driven from inside the engine container with `docker compose exec -T engine node -e ...` (Node 22 global `fetch` and `WebSocket`). Mirror contents are read independently with `redis-cli` in the redis container.
- Coordinator additions, all done: (1) `INCR game:engine:boots` once per boot as soon as Redis is up (retried on each reconnect until it lands, never blocks startup), exposed live in `GET /health` as `boots` (`null` if Redis is down or the key is gone); `POST /progress/restore` writes it back from engine memory. (2) Ring of the last 200 events, `GET /api/events?since=<iso>`. (3) `startedAt` per level, set by every `POST /levels/:id/start`. (4) `game:welcome:gift` is set with `SET ... EX 86400 NX` at player creation, once per engine boot (when Redis first comes up, if a player exists) and on every restore, so it exists whenever the game runs; fresh 24 h TTL when it was missing.

## HTTP API as built
All JSON. Errors are `{ error: <code>, message: <text>, ...extra }`. Timestamps are ISO 8601 strings. An empty body with a JSON content type is `{}`. If level files have errors, every `/api/*` route answers `503 { error: 'levels_invalid', message, errors: string[] }` (errors rendered with `formatLevelError`); `/health`, `/internal/*` and `/ws` still work. Unknown `/api/*` path: `404 { error: 'not_found' }`.

### Non-/api
- `GET /health` -> 200 `{ ok: true, service: 'engine', redis: 'up'|'down', postgres: 'up'|'down', boots: number|null, levels: 'ok'|'error' }`.
- `GET /internal/app-config` -> 200 `{ target: { redisUrl }, activeSlots: string[], dbExtraLatencyMs: number, etag }` with header `ETag: "<etag>"` and `Cache-Control: no-cache`. A matching `If-None-Match` (quoted, `W/`, list or `*`) -> 304, no body. The etag is the first 16 hex of sha1 over redisUrl, slots and latency.
- `POST /internal/metrics` body `{ instanceId: string, at?: epochMs, routes: { "<METHOD path>": { count, errors, p50Ms, p99Ms, ...any other numeric fields } } }` -> 200 `{ ok: true }`; 400 `invalid_metrics`. One push per second per instance; entries are kept 5 minutes, keyed by instance and second.
- `GET /ws`: WebSocket (below). Everything else not under `/api|/ws|/internal|/health` serves `ui/dist` (if it exists) with SPA fallback to `index.html`.

### Progress and player
- `POST /api/player` `{ name }` (1-40 chars) -> 201 progress file object; 400 `invalid_name`; 409 `player_exists`. Player id is `p-<8 hex>`.
- `GET /api/progress` -> 200 progress file object; 404 `no_player` before the first player (this is how the UI detects first run).
- `GET /api/progress/mirror` -> 200 `{ redis: 'up'|'down', present: boolean, inSync: boolean, expectedLevels, mirroredLevels }`. Not in the spec: it lets the UI notice a `FLUSHALL` and offer restore. 404 `no_player`.
- `POST /api/progress/restore` -> 200 `{ ok: true, restored: true, levels: number }` after re-reading `progress.json` from disk and rewriting the mirror; 404 `no_player`; 503 `redis_unavailable`; 500 `progress_invalid`.

### Levels
- `GET /api/chapters` -> 200 `{ player: { id, name }|null, xp, chapters: [{ id, dirName, title, incident: [{from,time,text}], levels: [{ id, title, mode, xp, status, attempts }] }] }`. Works with no player (all `locked`).
- `GET /api/levels/:id` -> 200 `{ id, chapter, chapterTitle, title, mode, story, teach, task, brainstorm: { prompt, options: [{id,label,is_reasonable}] }, hints: string[] (revealed only), hintsTotal, verifiers: [{ index, type } | quiz: { index, type:'quiz', question, options:[{id,label}], multiple } | answer: { index, type:'answer', prompt }], docs, showMe, scenario, minRedisVersion, reward: { xp, badge? }, status, attempts, brainstormAnswer: { optionId, text, at }|null, startedAt|null, completedAt|null }`. All markdown and text fields have templates rendered. Checks, expected values, quiz `correct`/`explanation` and solutions are never sent. 404 `no_player`, 404 `unknown_level`, 409 `level_locked`, 500 `template` (message from `TemplateError`).
- `POST /api/levels/:id/start` -> 200 `{ status, startedAt, setup: { ran, skipped: [{index, kind:'sql'|'script'}] }, level: <progress level entry> }`. Runs the level's `setup` `cmd` steps (rendered, refused if `FLUSHALL|FLUSHDB|SHUTDOWN` or any `game:` argument: 500 `setup_refused`). `available` becomes `in_progress`; `in_progress` and `passed` keep their status, setup runs again and `startedAt` resets. 409 `level_locked`; 503 `redis_unavailable`.
- `POST /api/levels/:id/brainstorm` `{ optionId, text }` (text 1-500 chars) -> 200 `{ brainstorm: { optionId, text, at }, isReasonable }`; 400 `unknown_option|invalid_text`; 409 `level_locked|level_not_started` (needs `in_progress` or `passed`).
- `POST /api/levels/:id/hint` -> 200 `{ index, hint, revealed, hintsTotal }`; 409 `no_more_hints`; same 409s as brainstorm.
- `POST /api/levels/:id/verify` `{ answers?: { "<verifyIndex>": string | string[] } }` -> 200 `{ verdict, attempts, status, ...whatever runVerification returns }`. Today `verdict` is `'not_implemented'`. 400 `invalid_answers`; same 409s. The handler increments `attempts`, appends `{ at, verdict }`, and when the verdict is `right` marks the level `passed` (xp, badge, `completedAt`, unlock next). P0-09 only has to replace `runVerification(level, ctx, answers)` in `engine/src/verify.ts`; `ctx` is `{ templateCtx, redis (RedisManager: send(argv)), events (EventBus: since(iso)), startedAt, attempt }`.
- `POST /api/levels/:id/complete` (only when `ENGINE_DEV=1`, else 404) -> 200 `{ status: 'passed', xp }`. Idempotent: xp is awarded once.

### CLI
- `POST /api/cli` `{ command: string }` -> 200 `{ reply: string, type: 'integer'|'bulk'|'status'|'nil'|'array'|'error', ms }`. Splits like redis-cli (quotes, `\n`, `\xHH`), runs on a dedicated terminal connection, formats like redis-cli on a terminal (`(integer) 5`, `"bulk"`, `OK`, `(nil)`, `1) "a"` with nested indentation, `(empty array)`, `(error) ERR ...`). Errors and connection failures are 200 with `type: 'error'` (`Could not connect to Redis at host:port: ...`, `Invalid argument(s)`); empty command is 400 `invalid_command`. Emits `cli.dangerous` for `KEYS|FLUSHALL|FLUSHDB|MONITOR|DEBUG` and the `cli_ping` custom event for `PING`.

### Target, slots, latency
- `GET /api/target` -> `{ redisUrl, state: 'up'|'down' }`. `PUT /api/target` `{ redisUrl }` (`redis://` or `rediss://`) -> `{ redisUrl, state }` after reconnecting (waits up to ~3.2 s for ready; an unreachable target is 200 with `state: 'down'` and keeps retrying). Persisted in `progress.json`; 400 `invalid_url`. Does not restore the mirror (the UI calls restore).
- `GET /api/slots` -> `{ active: string[] }`. `PUT /api/slots` `{ active }` (each matches `SLOT_NAME`, e.g. `cache.getPlayerStats`) -> `{ active }`; 400 `invalid_slots`.
- `PUT /api/db-latency` `{ ms }` (integer 0-5000) -> `{ dbExtraLatencyMs }`. Not in the spec: the source of `dbExtraLatencyMs`. In memory, resets to 0 on engine restart.
- Target and slots set before a player exists are held in memory and written into `progress.json` when the player is created.

### Workspace (paths relative to `WORKSPACE_DIR`)
- `GET /api/workspace/tree` -> `{ entries: [{ path, type: 'file'|'dir', size?, editable? }] }` (flat, sorted; skips dotfiles, `node_modules`, symlinks; max 2000 entries, depth 8).
- `GET /api/workspace/file?path=` -> `{ path, content, size, mtime }`. `PUT /api/workspace/file?path=` `{ content }` -> `{ path, size }` (atomic, creates parent directories, 1 MB max).
- Errors: 400 `invalid_path` (`..`, absolute, empty segment, NUL), 400 `extension_not_allowed` (allowed: `.js .mjs .md .redis .sh .yaml .json`), 403 `path_escapes_workspace` (symlink pointing out), 404 `not_found`, 413 `too_large`, 400 `not_a_file`.

### Events, metrics, logs
- `GET /api/events?since=<iso>` -> `{ events: [{ at, type: 'level.event'|'redis.state', data }] }` oldest first, last 200. Recorded: every `level.event` (custom events from `POST /api/events`, `cli_ping`, `level_started`, `redis_disconnect`, `redis_reconnect`) and every `redis.state` change.
- `POST /api/events` `{ kind: 'custom', name, data? }` (name `[A-Za-z0-9_.-]{1,64}`) -> `{ ok: true }`; 400 `invalid_kind|invalid_name`.
- `GET /api/metrics?seconds=60` (1-300) -> `{ windowSeconds, instances: string[], totals: { count, errors, p50Ms, p99Ms, rps }, routes: { [route]: { count, errors, p50Ms, p99Ms } }, series: [{ at, count, errors, p50Ms, p99Ms }] }`. p50 is the count-weighted mean of instance p50s, p99 the highest instance p99 (summaries cannot be merged exactly).
- `GET /api/logs/:service?lines=500` (`app|runner|proxy|postgres`) -> `{ service, lines: string[] }`; 404 `unknown_service`.

## WebSocket `/ws`
Messages are JSON `{ type, at, data }`. On connect the client gets one `redis.state`. Then, broadcast to everyone:
- `progress.changed` `data: { reason: 'player_created'|'level_started'|'brainstorm'|'hint'|'verify'|'completed'|'restored'|'target'|'slots', levelId: string|null, progress: <whole progress file> }`
- `level.event` `data: { kind: 'custom'|'redis_disconnect'|'redis_reconnect'|..., name?, data? }` (custom events: `name` is `ui_connected`, `cli_ping`, `level_started` with `data.levelId`, ...)
- `cli.dangerous` `data: { command: 'KEYS'|..., argv: string[] }`
- `metrics.tick` `data: { at, instances, count, errors, p50Ms, p99Ms, routes: { [route]: {count,errors,p50Ms,p99Ms} } }` (once a second, only when there was traffic in the previous second)
- `log.line` `data: { service, line }`
- `redis.state` `data: { up: boolean, url }` (password redacted). Switching target resets state quietly: no `redis_disconnect` level event for the switch itself.

## Progress file schema (`${PROGRESS_DIR}/progress.json`)
```
{ version: 1,
  player: { id, name, createdAt },
  target: { redisUrl },
  activeSlots: string[],
  levels: { [levelId]: { status: 'locked'|'available'|'in_progress'|'passed', attempts, verdicts: [{ at, verdict }],
            brainstorm?: { optionId, text, at }, completedAt?, startedAt?, hintsRevealed? } },
  xp: number, badges: string[] }
```
`startedAt` and `hintsRevealed` are my additive optional fields. Type `ProgressFile` is exported from `engine/src/progress.ts` (re-exported from `main.ts`). Written atomically (temp file in the same dir, fsync, rename), changes serialised in one queue. On boot the levels map is reconciled with the loaded levels (new levels added `locked`; the first level, and any level after a `passed` one, `available`). An unreadable file is renamed `progress.json.corrupt-<ms>` and the game starts as a first run; it is never overwritten. Mirror keys: `game:player:<id>` hash (`name, xp, created_at, levels_passed, levels_in_progress, levels_available, levels_locked`), `game:progress` hash (levelId to status), `game:welcome:gift` string with TTL, `game:engine:boots` counter. The mirror is written after the file on every change, boot does not rewrite it (so a wiped Redis stays visibly wiped until restore or the next change).

## What I did not do
- No verifiers (P0-09): `runVerification` returns `not_implemented`. `sql` and `script` setup steps are skipped and reported in `setup.skipped` (no `pg`, no runner call yet).
- No 503-on-bad-levels test (it needs a broken levels dir and an engine restart); the hook is a few lines in `server.ts` but is not exercised by the check.
- No hot reload of level files: changes need an engine restart.
- No UI, no Caddy changes, no engine host port. `app/`, `runner/`, `ui/`, `packages/`, `levels/` content untouched.
- `ui/dist` static serving and SPA fallback are implemented but not exercised by the check (the check's proxy is not up).
- Not verified: redis-cli's exact text for every reply type (formatting is from memory of redis-cli's terminal output, covered by unit tests I wrote, not diffed against the real tool); node-redis `typeMapping` of simple strings to Buffer is how `OK` is told from a bulk string (works here on node-redis 5.12.1).

## What surprised me
- The engine has no host port, so the check cannot use host `curl`. I did not add a port because CLAUDE.md fixes the list. It goes through `docker compose exec`.
- `levels/ch0-boot` appeared while I worked, so the default check path now runs against real Chapter 0 content (it starts the first level, so its `setup` runs for real).
- Fastify's `loggerInstance` does not type-check with a pino `Logger` directly; I cast.
- node-redis with `disableOfflineQueue` is what makes mirror writes fail fast when Redis is down instead of hanging until it returns.

## What P0-07 (app) and P0-10 (UI) must know
- App: poll `GET http://engine:4200/internal/app-config` every 2 s with `If-None-Match: "<etag>"`; 304 means no change. Switch Redis when `target.redisUrl` changes, enable slots from `activeSlots`, add `dbExtraLatencyMs` to the DB path. Push `POST /internal/metrics` once a second per instance (`instanceId` should be stable per container, e.g. hostname) with the per-route shape above; routes that had no traffic can be omitted. `p50Ms` and `p99Ms` are required numbers.
- App: `redis.state`-style outages: the engine's reconnect strategy is 250 ms backoff up to 2 s; `connectTimeout` 3000.
- UI: first-run detection is `GET /api/progress` 404 `no_player`. Use `progress.changed` (it carries the whole progress object) instead of refetching. `GET /api/levels/:id` for a locked level is 409, not 403. `answers` keys are the verifier `index` from the level payload. Hints come one at a time from `POST .../hint`. Offer restore when `GET /api/progress/mirror` says `present: false` (or `inSync: false`). `type` in `/api/cli` tells you how to colour the reply. Report `ui_connected` via `POST /api/events`.
- P0-09: for an `event` check use `GET /api/events?since=<level startedAt>` semantics (`ctx.events.since(ctx.startedAt)` in process). `ctx.redis.send(argv)` goes through the engine client (db 0), not the learner's terminal connection. The learner's terminal runs on a separate connection, so a `SELECT` there does not change what verifiers see.
- Compose: the P0-02 check expected engine/app/runner to print and exit 0. The engine now stays up, so that part of `scripts/check/P0-02.sh` may need updating by the orchestrator.
