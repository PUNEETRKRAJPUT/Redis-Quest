## Assumptions I could not check
- Nothing was run: the tests, the check script and every click are unverified. `tsc` and `eslint` for `@quest/ui` are clean.
- **Digest coverage.** Checked against `docs/redis-docs-digest.md`: `XADD key * field value`, `JSON.SET key path json`, `JSON.NUMINCRBY key path n`, `PFADD key element`, `GEOADD key longitude latitude member`, `TS.ADD key * value` (`*` is server time). **Not verified against the digest** (it lists only the command names): `SETBIT key offset value` and its reply (the previous bit), `BF.ADD key item` and `BF.EXISTS key item` with their replies, the `TS.ADD` reply (the timestamp), the `PFADD` reply values, `GEOADD`'s coordinate limits (clamped to longitude plus or minus 180 and latitude plus or minus 85.05112878, from the Redis documentation as I remember it), `BF.ADD` creating a missing filter.
- `JSON.NUMINCRBY` reply wording assumes the engine shows a bulk string such as `[513]` for a `$` path; the note just repeats whatever came back.
- The map click maps through the SVG's own `getBoundingClientRect` and the viewBox (360 by 220, padding 30); the arithmetic is unit-tested, the live click is not. With one place on the map there is no scale, so a click lands about 100 m per unit from it.
- **Bundle size.** Importing `monaco-editor/editor/contrib/suggest/browser/suggestController` adds the suggest widget and what it imports (including a small markdown renderer). I expect a few hundred KB at most, not megabytes, but did not build. The 120 KB member list is a separate lazy chunk. If the Turbopack build objects to `import('./client-api.generated.json')`, the fallback is `fetch` of a copy under `ui/public`, which stays same-origin.
- The generator walks `RedisClientType` with the default modules because `LearnerRedis` is `RedisClientType<any,...>`, whose `any` generics would hide the members. That is the type `createClient()` returns, and what `deps.ts` builds before the cast; `redisCached` is the same type with RESP 3.
- node-redis exposes each command twice (`SET` and `set`); only camelCase names are offered.
- The suggest widget's CSS imports under Turbopack follow the other contributions already imported; not exercised.

## Decisions and surprises
- `LearnerRedis` is typed with `any` generics, so walking it directly gives nothing useful; the generator walks the library's default client type instead (reasoned in the script header and the JSON's `source.walked`).
- The multi chain's type is unresolved when reached through `ReturnType<client['multi']>`; the generator calls `client.multi()` in its in-memory probe file to get the real chain type, and stores each shared signature once (names in `multi.shared`, chain-only members in `multi.only`) to keep the file small.
- `log` is a plain function, so "after `log.`" offers the members every function has (read from the standard `Function` type), not an invented API. The `log` call signature is recorded in the JSON (`log.call`) but not used yet.
- The generator formats its output with the repo's prettier config, so `prettier --check .` stays clean and regenerating is byte-stable.
- Tuple-typed rest parameters (how node-redis types most commands) are unwrapped into readable parameter lists; commands with several accepted forms (such as `hSet`) list them in the suggestion's documentation.
- The geo panel needs a place name before a click does anything (the cursor turns to a crosshair once there is one); the preview line shows the command for the point under the mouse.
- The read-only reason is a prop on `PanelFrame` rather than a new component, so test ids and the component ids are untouched.
- Files outside my list: none edited. I did need nothing changed elsewhere.
