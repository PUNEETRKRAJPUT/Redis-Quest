## Hand-grading script for 01, 07, 08 and 09
Setup: the default stack up with `ENGINE_DEV=1`, `levels/ch5-survive` mounted, the grader's player unlocked (as for any level). Each level: start it first (`POST /api/levels/<id>/start`, so the level's `setup` runs and the event
look-back window begins), play the `.sh` reference's commands in the order of `solutions/NN-reference.sh` (every line is in the task's order; `API=http://localhost:3000`), press Verify with the answers shown, expect `right`.
For each wrong `.sh`, **restart the level** (start again: events count only since the level's `startedAt`), play it, Verify, expect `wrong`. A failed event check waits its full `timeoutMs` (120 s for the target events, 300 s for sentinel_failover, 60 s for the disconnect) unless the engine runs with `VERIFY_MAX_EVENT_WAIT_MS` (G-01 sets 3 s).
Between levels: target back on `redis://redis:6379`, replica/sentinels/cluster in the state each level's "Start with" says.

## Deviations from the spec, and why
1. **Level 02**: Verify comes **before** the kill and restart. After a restart `CONFIG GET save` is empty again (measured) and `rdb_saves` restarts at 0, so the spec's checks could not hold after it, and the harness cannot restart anything. The restart is a demonstration after Verify, and the second quiz is about why `save` is empty. Extra checks: `GET score:final` "24", `rdb_saves` 1+. Setup: `DEL score:final`, `CONFIG SET save "60 1000"` (restores the stack's setting between harness solutions). Ends by removing the crash node (`docker compose --profile crash rm -sfv redis-nopersist`) so level 03 starts from one with no `dump.rdb`. The reference has a `BLPOP wait:half:a:second 0.5` line so that the snapshot child has finished before the harness verifies.
2. **Level 03** runs on the **crash node** (the default node already has the log on, so `CONFIG SET appendonly yes` would be a no-op), with the benchmark run inside `redis-nopersist`. Same ordering rule (Verify on the crash node, then the way back and `rm -sfv`). Setup restores `appendfsync everysec`.
3. **Level 10**: the spec's `ACL LIST contains user worker on` cannot work (a list reply `contains` compares whole elements, and `ACL LIST` elements are whole lines), and `notContains -@dangerous` on a list reply is element equality too, so it always passes. I check `ACL USERS` contains worker and `ACL GETUSER worker` contains the exact commands string `-@all +@read +@write -@dangerous` (and `~queue:*`), which also rejects `+@all` and a wrongly ordered rule. `ACL WHOAMI` is the identity probe because it is refused for the worker and the error names it (`PING` and `CLIENT INFO` are refused too). Setup removes the worker and `queue:x`/`other`.
4. **Level 11** uses `CLIENT PAUSE 4000 WRITE` (4 s, not 2 s: a learner has to type the `SET` in the window; the terminal's own ceiling is 8 s), and adds `cmdstat_latency|doctor`, `cmdstat_memory|doctor` and `cmdstat_client|pause` checks (setup resets stats), plus a 250 ms `EVAL` stall so that `LATENCY LATEST` and `SLOWLOG` have something to show.
5. **Level 14**: the spec asks for `CONFIG SET save "60 1000"` as the last line of the reference *and* a check that `save` contains `300 10`; those cannot both hold. The reference ends at `300 10`, the task tells the learner to restore `60 1000` after Verify, and the handoff note for the orchestrator is below. The setup makes the box blank (five `CONFIG SET`s), so every check fails on it and the empty stub is wrong.
6. **Level 01** matches `redis_target_changed` with `to: redis://redis-nopersist:6379` (E-03's field) rather than `kind: single`, which the move back to the default also is.
7. **Level 07** adds `GET score:final` "30" (a write on the replica never lands). **Level 09** adds a second behavior verifier (a wallet of 5 is refused and untouched). Quiz counts: 04 has 7, 07 and 08 and 11 have 4, 09 has 5, 12 has 6, 13 has 10.
8. **Level 06** uses Chapter 2's key `cache:player:` (the app fixture `cache-aside.js` uses `cache:player-stats:`), so ch4b's and ch2's fixtures and a learner's own file line up.
9. Not owned, not added: no scenario (celebrity-100 reused); `show_me` components as in the spec; `levels/README.md` untouched.
