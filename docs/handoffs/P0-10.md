# P0-10 handoff: UI shell

## What I built
`ui/` is a React 19 + Vite single-page app served same-origin by the engine (no `engine/src/static.ts` change was needed: the existing static + SPA fallback works). Hash routing, a zustand store, one shared reconnecting WebSocket.

Screens (`ui/src/screens`, `ui/src/level`, `ui/src/panels`):
- **Welcome**: name prompt, `POST /api/player`. First run is detected by `GET /api/progress` 404 `no_player`.
- **Chapter map**: chapters as a vertical path, levels with status icon, mode, XP, attempts-free status, chapter thread (chat) on demand, XP and badges.
- **Level**: the seven beats as collapsible stages: 1 scenario (chapter thread as chat + story), 2 what already exists (derived list + live pain panel from `metrics.tick`), 3 brainstorm (options + one line, locked in, can be changed), 4 teach (markdown + docs links), 5 build (task markdown, tools workbench, quiz and answer inputs, hints one at a time), 6 verify (live check rows, verdict banner for right / works_but_wrong / wrong / not_implemented, show-me on pass, next level), 7 ideal way (unlocks on pass, after 3 failed attempts, or on request).
- **Terminal** (xterm.js, own line editor, history, paste, colour by reply type, inline `[warning]` for KEYS/FLUSHALL/FLUSHDB/MONITOR/DEBUG, prompt from `GET /api/target`), **Editor** (Monaco bundled, lazy, offline; tree/read/save through `/api/workspace/*`; "open in VS Code" line), **Logs** (tabs app/runner/proxy/postgres, seed from `GET /api/logs`, tail from `log.line`), **Metrics** (rps, p50, p99, errors, db queries, redis commands sparklines), **What you built** (passed levels with their show-me and an Insight link), `#/showme` (all 12 views on sample data, not in the nav).
- Banner with a "Restore my save file" button when `GET /api/progress/mirror` says not present / not in sync (refreshed on WS open, redis up, and after FLUSHALL/FLUSHDB).
- Design: one accent, deep saffron (`fiction/league.json` names no colour), system fonts, dark/light via `prefers-color-scheme`, 16px gutters, inline SVG icons only, skip link, aria on tabs/stages, no horizontal scroll at 1280 (asserted per screen in the e2e).

## Show-me component contract
The level schema carries only an id (`show_me: hash_card`), no key. The wrapper `ShowMe({id, levelId, playerId, keyName?})` in `ui/src/showme/index.tsx` picks the key from `defaultKey()` (a table: Chapter 0 levels, and best-effort Chapter 1 from the authored task text, unverified) and otherwise shows a "which key?" box. It reads Redis through `POST /api/cli` (read-only commands, replies parsed by `redisReply.ts`) polling every 2 s. Each id has a pure view (`ui/src/showme/views.tsx`) with these props:

| id | wrapper reads | view props |
|---|---|---|
| `kv_card` | TYPE, GET, TTL | `name, type, value|null, ttl|null` |
| `hash_card` | HGETALL, TTL | `name, fields: [k,v][], ttl?` |
| `list_feed` | LRANGE k 0 19, LLEN | `name, items: string[] (newest first), total` |
| `set_chips` | SMEMBERS | `name, members: string[], highlight?` |
| `leaderboard_panel` | ZRANGE k 0 9 REV WITHSCORES | `name, rows: {member,score}[], highlight?` (highlight = `user:<playerId>`) |
| `ttl_timer` | TTL (4 s) | `name, ttl (s, -1 none, -2 gone), readAt (epoch ms), total?`; counts down locally |
| `bitmap_streak` | BITFIELD k GET u1 #0..#29 | `name, bits: (0|1)[]` oldest first, trimmed after the last set bit |
| `hll_counter` | PFCOUNT | `name, count` |
| `geo_map` | ZRANGE k 0 49, GEOPOS | `name, points: {member,lon,lat}[]` (SVG dots) |
| `stream_log` | XREVRANGE k + - COUNT 10 | `name, entries: {id, fields:[k,v][]}[]` newest first |
| `json_tree` | JSON.GET k $ | `name, value: unknown` |
| `cache_stats` | INFO stats, DBSIZE | `hits, misses, keys, commands?` (server lifetime counters) |

## How the UI maps the engine
- Boot: `GET /api/progress` (404 -> welcome, 503 `levels_invalid` -> error page listing `errors`, network error -> "engine not answering", retried every 2.5 s). Then `/api/chapters`, `/api/progress/mirror`, `/health`.
- Entering a level: `GET /api/levels/:id` (409 `level_locked` -> locked message). If status is `available`, `POST .../start` once, then `POST /api/events` `ui_connected` (events are looked up since `startedAt`). `in_progress` and `passed` are not restarted.
- `progress.changed` replaces the store progress and refetches chapters; the open level reloads when its own progress entry changes (hint, brainstorm, verify, completed). `redis.state`, `metrics.tick`, `log.line`, `level.event`, `cli.dangerous` feed the header dot, metrics, logs, the live verify line and the mirror check. WS reconnects with 0.4 s doubling backoff to 5 s and re-announces `ui_connected` on every open.
- Brainstorm `POST .../brainstorm`; hint `POST .../hint`; verify `POST .../verify` with `answers` keyed by verifier index (quiz = option id or list, answer = text); terminal `POST /api/cli`.

## Check
Command: `scripts/check/P0-10.sh` (exit 0). Stack: compose project `quest-p10`, `.env.p10` (ports 3300/6393/5435/5543, `ENGINE_DEV=1`), plus override `ui/e2e/compose.p10.yml`. The override and `QUEST_*_DIR` point logs, workspace, progress and levels at `ui/e2e/.scratch`, so I never touch the shared `./logs`, `./.progress`, `./workspace`. The engine got a copy of `levels/ch0-boot` only (isolation from ch1 mid-write, as agreed). The script restarts the engine once before Playwright so level 5's `boots >= 2` is true (a browser test cannot run docker). `P10_KEEP_STACK=1` leaves the stack up for UI work. It ends with `docker compose -p quest-p10 down -v`.

By the time of the final run P0-09's verifier had landed in the working tree: every level returned the real verdict `right`, so no dev-complete fallback was used and no `NOTE` line printed. The fallback is still in `ui/e2e/chapter0.e2e.ts` behind `const ALLOW_DEV_COMPLETE_FALLBACK = true` (set it to false to remove it: one line); it prints `NOTE: verify not implemented yet, used dev complete` and the script repeats it in a banner.

## What I did not do
- Level 1 and 5 real host actions (`./scripts/start`, `docker compose down`) are not performed by the test: the script's engine restart stands in for level 5. `./scripts/start` was not checked to exist.
- The ideal-way panel cannot show reference solutions: no endpoint serves them and `GET /api/levels/:id` never sends them. It renders `ideal { reference, language, annotations, tradeoffs }` from the verify response if P0-09 adds it, else a notice pointing at `levels/<chapter>*/solutions/`, plus the learner's beat-3 guess next to the task. No side-by-side diff.
- Beat 2 has no authored content field, so "what already exists" is derived (client state, health, mode, scenario id); the pain panel reads `metrics.tick`, and db/redis series only show if routes carry `dbQueries` / `redisCommands` numbers.
- Insight link is `http://localhost:5540/` (override with `localStorage quest.insightPort`); the engine does not expose the port and I did not verify a deep link to a key (not verified).
- No code-mode level was exercised in the browser (Chapter 0 has none): the editor is checked via standalone `#/editor` (open, type, save, read back through the API). Monaco has JS/redis/shell/markdown highlighting only, no TS worker or IntelliSense.
- `redis-cli` formatting is parsed back from the engine's text (`redisReply.ts`, unit-tested); exotic RESP3 types (maps, doubles) are only roughly handled.
- No hot reload of verify live progress beyond echoing `level.event` names (P0-09 emits `verify_started` / `verify_finished`); the response's `checks` is authoritative.

## What surprised me
- A focused xterm snaps the page scroll back; a real Playwright click on a stage header further down then landed elsewhere. The test opens stages with `dispatchEvent('click')`. Real users may see a small scroll jump when clicking away from a focused terminal; not fixed.
- The base compose bind-mounts `./logs` (and for app/runner `./workspace`, `./.progress`) with no env override, hence the override file. `docker/node.Dockerfile` bakes `levels/` and the UI build into the shared image `redis-quest-node:latest`; concurrent builds by other agents retag it.
- `game:engine:boots` survives engine restarts (Redis keeps it), so UI tests must not assume a value.
- xterm's DOM rows have no newlines, so test assertions match substrings.
- monaco-editor 0.57 has a new package layout: subpaths are `monaco-editor/editor`, `monaco-editor/languages/definitions/<lang>/register`, and only `.` has types (declared in `ui/src/vite-env.d.ts`).

## What P0-09 must know (fields the UI reads from `POST /api/levels/:id/verify`)
`verdict` (`right|works_but_wrong|wrong|not_implemented`), `attempts`, `status`, `checks[]` of `{ index, type, ok, message }` (one row per verifier, `index` matches `GET /api/levels/:id` `verifiers[].index`; failing `message`s are shown, and for `works_but_wrong` they are the "this passes today, but" text), optional `feedback` (string), `durationMs`, optional `ideal`. Anything else is ignored. Event verifiers rely on `ui_connected` being posted after the level `start` (the UI does that). `level.event` names are shown live while verifying.

## What content authors must know
- `story`, `teach`, `task` are GitHub-flavoured markdown (tables, lists, inline code). Raw HTML is dropped. Fences highlight `redis`, `js`/`mjs`, `bash`/`sh`, `json`, `sql`, `yaml`; an unlabelled or indented block that starts with an upper-case word is highlighted as redis. Code blocks get a copy button. Only `http(s)` links and `#` links are live; `https` links open in a new tab.
- Chapter `incident` renders as the chat: `from: you` right-aligned, other slugs by nickname (roommate Teja, senior Harry Bhaiya, warden Warden Sir, sms-vendor TextTara Sir, rival-college Gomti Gang). Plain text only.
- `show_me` ids: kv_card, hash_card, list_feed, set_chips, leaderboard_panel, ttl_timer, bitmap_streak, hll_counter, geo_map, stream_log, json_tree, cache_stats. The key comes from `defaultKey()` in `ui/src/showme/index.tsx`; a new level needs a line there (or a schema field for the key, which I suggest) or the learner gets a "which key?" box.
- `answer` verifiers render a text box and `quiz` verifiers radios (checkboxes when `multiple`), both at the end of the build beat.
