# F-12 handoff: interview mode

## What I did
A `code` level can now be a timed blank rebuild: no teaching, a visible countdown, hints that cost XP, and the
elapsed time recorded. Schema, engine and UI are done; the example level `levels/_examples/example-interview/`
rebuilds `example-code-01-cache-aside` and is graded end to end in the check.

## The schema field (`packages/shared/src/levels/schema.ts`, additive)
```yaml
interview:                 # optional, code levels only
  minutes: 10              # whole number, 5..60
  rebuild_of: example-code-01-cache-aside   # a level id
  hint_xp_cost: 10         # whole number 0..1000, default 10
```
- `teach` is optional **only** on a code level that sets `interview` (any other level: `teach: required`). `interview` on a
  non-code level is the usual "unknown key" error (the field lives on the code variant only).
- New exports: `interviewSchema`, `Interview`, `INTERVIEW_MINUTES_MIN/MAX`, `INTERVIEW_DEFAULT_HINT_XP_COST`,
  `interviewReferenceErrors(chapters)`, `chapterOrder`; `loadAllLevels(root, { skipInterviewCheck? })`.
- `rebuild_of` is checked in `loader.ts` because it needs the whole tree: it must name a loaded level in the same chapter
  that is **listed before** this one, or in an earlier chapter (canonical order, then by path for non-canonical
  chapters). Self-reference and later levels are errors, with file:line:col on `interview.rebuild_of`.
  `loadAllLevels` (what the engine uses) checks it over the whole tree. The `levels:validate` command checks it over the
  union of the directories given, so `levels:validate levels/_examples/example-code levels/_examples/example-interview`
  passes and `levels:validate levels/_examples/example-interview` alone fails with "pass the chapter holding it too".
  That is by design, and the README says so.
- README: field table rows and a new section "Interview levels" in `levels/README.md`.

## Engine (`engine/src/interview.ts`, `server.ts`, `progress.ts`, `levels.ts`)
Progress fields (additive on `levels[id]` in progress.json): `interviewStartedAt`, `hintsBought`, `interviewElapsedMs`
(set on the first pass), `overtime` (set on the first pass); a verdict record gets `overtime: true` when the verify came
after the deadline.
- `POST /api/levels/:id/start` on an interview level records `interviewStartedAt`. **The first start wins**: starting again
  (or reopening) never refills the clock.
- `GET /api/levels/:id` adds `interview` and `remainingMs` (both `null` on ordinary levels):
  `interview = { minutes, hintXpCost, rebuildOf: { id, title }, startedAt, deadlineAt, overtime, overtimeMs, hintsBought, elapsedMs }`.
  `remainingMs` is clamped at 0 (`null` before the start); `overtimeMs` is how far past the deadline it is. After a pass the
  clock is frozen: `elapsedMs` is the recorded time, `remainingMs` and `overtime` are as they were then. `teach` is always
  `""` for an interview level (nothing to leak).
- `POST /api/levels/:id/hint` on an interview level subtracts `hint_xp_cost` from XP (never below 0) and counts it in
  `hintsBought`; the response adds `xpCost` (what was really taken), `xp` (left) and `hintsBought`. Ordinary levels: unchanged.
  The engine does not ask for confirmation; the UI does.
- `POST /api/levels/:id/verify` still grades normally. On an interview level the response adds `overtime` (was the deadline
  passed **when the verify was asked for**, not when a slow load run ended) and `elapsedMs`. The first passing verify freezes
  `interviewElapsedMs` and `overtime`.
- `/api/chapters` is unchanged (no interview flag on the map).

## UI (`ui/src/level/interview.tsx`, `screens/Level.tsx`, `Built.tsx`, `IdealWay.tsx`, `styles.css`)
- Level header: a pill "Interview: 10 min, hints cost 10 XP", "Hints bought: n" once any, and a countdown
  (`data-testid="countdown"`, `role="timer"`, `data-state` waiting|running|overtime|done). It ticks once a second from the
  engine's `remainingMs` and re-anchors on every reload of the level. Overtime shows plainly as "Overtime +m:ss" in red.
- Beat 4 (Teach) is replaced by one line, "No teaching here: this is the interview." (chip "skipped"); the docs links are not shown.
- Hint button reads "Show a hint (costs 10 XP) (0 of 2)". Clicking opens an inline prompt (`hint-confirm`): "This hint costs
  10 XP. You have 220 XP, so you would keep 210. Take it?" with "Spend 10 XP and show it" and "Keep my XP" (focused by default,
  Escape closes). When XP is lower than the cost it says it takes all of it and you keep 0.
- A verify after the deadline shows an "Overtime: ..." note under the Verify beat (`overtime-note`).
- On pass: "Rebuilt in m:ss." in the passed panel (`rebuilt-in`; "..., over the 10:00 limit" if late), the countdown turns into
  "Rebuilt in m:ss", and the same line appears on the level's card in "What you built" (`built-rebuilt-<id>`).
- Beat 7 (ideal way) starts with a link to `rebuild_of`'s level, whose ideal-way beat holds the guided reference and the wrong
  solutions. I did not copy those solutions into the interview level's own ideal response; the interview level's own
  `solutions` (required by the schema) are the same reference and no-cache files, copied into its directory.

## Example level
`levels/_examples/example-interview/` (chapter id `example-interview`, level `example-interview-01-cache-aside-rebuild`):

## What I did not do / things to know
- Overtime is covered by engine and UI unit tests (clock injected, `interviewStartedAt` aged in the route tests) but **not
  in the browser**: nothing in the stack lets a test age the clock short of waiting 5 minutes (the schema minimum).
- `engine` check runs `test/interview.test.ts` only. The full engine suite currently has one failure that is not mine:
  `test/verify-slots.test.ts` fails because A-01's `app/src/slots/registry.ts` (now committed) added slots
  (`prefetch.applyChange`, `prefetch.bulkLoad`, `session.destroy`, `session.destroyAll`) that `engine/src/verify/slots.ts` does
  not list yet. A-01 (or whoever merges it) must update `engine/src/verify/slots.ts`. I did not touch it.
- The `format` step of the check runs `prettier --check` on the files this task touches, not `pnpm format:check` for the
  whole tree (other agents have files in flight).
- Interview levels allow brainstorm (beat 3) as before; the schema still requires `brainstorm` and at least one wrong solution.
- A hint bought after the level is passed still costs XP (the spec says each hint); easy to change in `server.ts` if unwanted.
- `rebuild_of` may point at any level kind (not only code); the spec did not restrict it.
- Real chapters' content untouched. No `git add`/commit.
