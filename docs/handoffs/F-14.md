# F-14 handoff: the UI runs on Next.js 16.4 (App Router)

## What I did
- **Routes** (`ui/src/app/`): `/` (map), `/level/[id]`, `/terminal`, `/editor`, `/logs`, `/metrics`, `/built`,
  `/showme`. Every page is a server component that only renders a client screen; nothing on the server talks to
  the engine. `/level/[id]` has no `generateStaticParams` (levels can be added after the build): the page passes the
  `params` promise into a `<Suspense>` and `src/shell/LevelRoute.tsx` (client) unwraps it with `use(params)`, the
  pattern in `dynamic-routes.md` "With Cache Components / Without generateStaticParams". It prerenders as a partial
  shell (◐) and works for any id at run time.
- **Shell** (`src/shell/GameShell.tsx`, client), mounted from `src/app/layout.tsx` around `{children}`: starts the
  store and the socket once, retries `init` every 2.5 s while `boot === 'offline'`, renders `loading`, `welcome`,
  `offline`, `invalid`, and when ready the skip link, header (nav + status), mirror banner and the page in
  `#main`. Every `data-testid` and label from `App.tsx` is kept; I added `data-testid="conn-state"` on the
  `live`/`reconnecting` text. The nav reads `usePathname()` inside its own `<Suspense>` (required under Cache
  Components on a route with request-time params, see `use-pathname.md`); the fallback is the same links, unmarked.
- **Links**: `src/shell/QuestLink.tsx` wraps `next/link` and takes `to={Route | '/path'}`. Every hash link in
  `ui/src` is gone (ChapterMap, Level x4, interview's RebuildLink, header). Route helpers live in `src/routes.ts`:
  `pathFor(route)`, `parsePath(pathname)`, `parseHash('#/...')` (returns null for non-route hashes).
- **Legacy hash redirect**: the shell reads `location.hash` on mount and on `hashchange`; `/#/level/x`,
  `/#/terminal`, `/#/` and so on `router.replace` to the real path (no history entry).
- **WebSocket in development**: `next.config.ts` sets `env.NEXT_PUBLIC_QUEST_WS_PORT` to `PROXY_PORT` in development
  and to `''` otherwise; `src/ws.ts` (`wsUrl()`) connects to `<hostname>:<port>/ws` when set, else same-origin. The
  production bundle has the empty string inlined (checked by the check script).
- **Monaco under Turbopack**: `MonacoEditor.tsx` now creates its worker with
  `new Worker(new URL('monaco-editor/editor/editor.worker.js', import.meta.url), { type: 'module' })`; Turbopack
  emits a `turbopack-worker` chunk that loads the bundled `editor.worker` chunks (verified in the browser). Still
  bundled, no CDN loader. It loads only in the browser: `EditorPanel` and `IdealWay` import it with `React.lazy`
  and render only after the shell has booted on the client. xterm and its CSS import fine as-is.
- **'use client'** added to the modules a page imports directly: `ChapterMap`, `Built`, `ShowMeGallery`,
  `TerminalPanel`, `EditorPanel`, `LogsPanel`, `MetricsPanel`, `MonacoEditor`. Everything they import is client by
  inheritance.
- **Vite app removed**: `ui/index.html`, `ui/vite.config.ts`, `ui/src/main.tsx`, `ui/src/App.tsx`,
  `ui/src/router.ts`, and also `ui/src/vite-env.d.ts` (it only declared `vite/client` types and the `?worker`
  module). `ui/vitest.config.ts` added (react plugin, `@/` alias, `test/**/*.test.{ts,tsx}`, node environment).
- **Tests**: `test/panels.test.ts` router test now covers `pathFor`/`parsePath`/`parseHash`;
  `test/interview.test.tsx` expects `href="/level/..."` instead of `#/level/...`.
- `*.tsbuildinfo` added to the repo `.gitignore`.

## What I did not do

- I did not run `ui/e2e/*` (needs the compose stack). They will need edits by their owner, see below.
- I did not test `next start` of the production build in a browser: the offline guide says dev is not a reliable
  reference for `useOffline`, but with the engine down the Next server itself is still up, so the case that
  matters here (engine unreachable, UI server reachable) is the one I drove. Not verified: Next's own offline retry
  with the UI server unreachable.
- Mid-session "engine down" in Playwright blocked HTTP only; the already-open socket stayed open, so the header

- No stubs for `next/link` / `next/navigation` were needed: `next/link` renders under `renderToStaticMarkup`

## Deviations from the spec
- **`export const instant = false` on all eight pages.** The dev server logged "Could not validate that a segment
  in your UI has instant navigation ... This segment was dropped from rendering" for every route, because the
  shell (as the spec asks, like `App`) shows only the boot state until the engine answers in the browser, so the
  page segment is never in the prerender. The docs (`route-segment-config/instant.md`) offer "render the dropped
  segment" or `instant = false`. Rendering pages before boot would mount screens that assume a ready store, so I
  opted out per page. It is a dev-only validation; prerendering and the build are unchanged. The shell redesign
  (F-17) can revisit this by rendering the page segment while booting.
- Extra deletion: `ui/src/vite-env.d.ts` (part of the Vite app; would reference `vite/client` types otherwise).
- Extra test id: `conn-state` on the header status text.

## Surprises in Next.js 16.4
- **Activity keeps up to 3 visited routes mounted and hidden** (`display: none`) with Cache Components. Effects are
  torn down when hidden and re-run when shown (xterm re-creates itself; transcript is module-level so it survives).
  DOM queries find hidden duplicates: in Playwright use `getByRole` or `.filter({ visible: true })`, or you get
  strict-mode violations (e.g. two `terminal` test ids after visiting a level and `/terminal`).
- `usePathname()` / `useParams()` suspend while prerendering any route with request-time params, even from a
  layout component, so the nav needed its own Suspense.
- `env` in next.config inlines any key regardless of the `NEXT_PUBLIC_` prefix; the prefix only matters for real
  environment variables. A change to `next.config.ts` makes the running dev server restart itself.
- Turbopack accepts `new Worker(new URL('<bare package path>', import.meta.url))` and builds a worker chunk.
- Server components cannot import modules that use hooks unless marked: `ShowMeGallery` has no hooks itself but
  imports `showme/views.tsx` (which does), so the page 500'd until `ShowMeGallery` got `'use client'`.
