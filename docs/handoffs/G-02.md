# G-02 handoff: bundle solutions in the grading harness

## Convention
A bundle's named export for a slot is the part of the slot name after the first dot (`prefetch.bulkLoad` -> `bulkLoad`,
`session.destroyAll` -> `destroyAll`). For a level whose verify specs name several slots, `scripts/grade/grade.mjs` copies
the bundle to `<workspace>/<dir of first slot's file>/_bundle-<level-id>-<solution-basename>.js` and writes each slot file
as a two-line shim (`import * as bundle from './_bundle-....js'; export default bundle.<name>;`; relative path if the slot
files sit in different dirs). Bundle written first, shims after, one 2 s settle at the end. After each bundle solution all
touched files are restored (deleted with `--workspace`, emptied through the API, which cannot delete). Documented in
docs/grading.md ("Bundle solutions") and levels/README.md (Solutions section).

Extra (coordinator request): after any solution file containing `CONFIG SET`, the harness runs `CONFIG SET maxmemory 536870912`
and `CONFIG SET maxmemory-policy noeviction` via /api/cli and prints one "reset maxmemory ..." line; sentence added to
docs/grading.md. No ch2-09 solution is in this check, so that path is syntax-checked only, not exercised live.
