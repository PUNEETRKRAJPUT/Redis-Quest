# F-18 handoff: the first five minutes

## What I built
- `ui/src/screens/Welcome.tsx` (export and signature unchanged): the opening scene, then the name form, then the kick-off beat.
  Timeline (about 9 s in total): lamps flicker on and `floodlights()` sweeps (0.45 s), the title rises letter by
  letter (1 s), chat arrives from 3.3 s (typing dots, then the bubble, `msg` cue; `pager` for the senior's line),
  the form slides in 0.7 s after the last line. "Skip intro" or Escape jumps to the form with the name field focused.
  S toggles sound while the scene plays. Reduced motion (OS or in-game): one still, everything visible at once.
- `ui/src/onboarding/`: `Stage.tsx` + `stage.css` (pylons, soft beams, rain in the light, pitch ellipse), `Chat.tsx`
  (own bubbles and typing dots; no dependency on F-20), `NameForm.tsx`, `Jersey.tsx` (SVG shirt with the typed name and
  number 07), `Kickoff.tsx`, `profile.ts` (persisted `rq:profile`, six palette jerseys), `scene.ts` (pure: speakers, incident
  selection, timeline).
- Incident: `GET /api/chapters` (works without a player when the engine allows it) supplies chapter 0's incident; the
  first five lines plus the first line from the senior are used. A written fallback in the fiction's voice is on
  screen from the start and is used if the call fails or arrives after the chat has begun.
- Form: same label, field, `maxLength`, `createPlayer`, `player_exists` -> `init`, error `role="alert"`, ids
  `welcome`, `player-name`, `player-submit`; "Start Chapter 0" / "Starting...". Added: jersey radiogroup (arrow keys,
  ids `jersey-<flood|turf|sky|cap|wicket|chalk>`), a sound switch bound to the design setting, a live jersey preview.
- Kick-off: after `createPlayer` succeeds the store flips to `ready` at once and unmounts Welcome, so the 2 s
  "Welcome to the league, <name>" beat (celebrate: floodlights, confetti, `tock`) lives in its own React root on
  `document.body` (`showKickoff`), `pointer-events: none` so clicks reach the game, any key skips it, id `welcome-kickoff`.

## Surprises and what the integration task must know
- **CSS modules do not work in this repo's dev config.** `next.config.ts` has `turbopack.rules['*.css'] = { loaders:
  ['@tailwindcss/turbopack'], as: '*.css' }`; the output is treated as plain global CSS (file shown as
  `x.module.css.css` in warnings), so class names are not hashed and `styles.foo` is `undefined`. I switched to a plain
  `stage.css` with an `rqw-` prefix. Other agents using `*.module.css` (map, thread, showme) will see the same:
  their keyframes apply globally and `styles.x` is empty. Fix belongs to `next.config.ts` (e.g. `as: '*.module.css'`
  for module files, or a separate rule); I did not touch it. Also: `:global(...)` in a module fails to parse there.
- **e2e (F-25):** the name form now appears about 9 s after load (or at once after Escape, or under
  `reducedMotion: 'reduce'`). `ui/e2e/chapter0.e2e.ts` and `interview.e2e.ts` fill `player-name` straight away: use
  `await page.keyboard.press('Escape')` first, or emulate reduced motion, or raise the timeout. After submit there is a
  2 s overlay (`pointer-events: none`) above the map.
- `Welcome` imports `api` directly for `chapters()` (read-only call, no store change).
- Two persisted keys now exist: `rq:settings` (design) and `rq:profile` (jersey). The jersey is cosmetic; F-17 may read
  `useProfile` from `@/onboarding/profile` for the HUD if it wants to show it.
