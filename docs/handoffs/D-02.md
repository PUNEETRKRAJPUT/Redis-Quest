## Assumptions I could not check
1. Caddy `file_server { status {err.status_code} }` inside `handle_errors` returns the error's own status (502). If a
   502 comes back as 200, the page would be seen as "up" by `curl` checks and by the page's own probe (it reloads on 200
   and loops). Fallback: drop `status` and use `respond` with a template, or serve with `templates`. `D-02.sh` B1 asserts 502.
2. Caddy accepts the one-line named matcher `@startpage not path ...` with several paths (`caddy validate` is what
   `scripts/check/F-01.sh` runs; run it).
3. In `handle_errors` the matcher sees the original request path (so `/api/*` stays a bare 502). B2 asserts it.
4. `docker compose up -d proxy` then later `docker compose build` and `docker compose up -d` (replacing the single
   `up -d --build`) behave the same as before for a first start, and `up -d` does not recreate the proxy.
5. bash 3.2 runs the `EXIT` trap when Ctrl-C ends `scripts/start` (so the page shows "failed").
6. `ui/src/design/settings.ts` rehydration: `merge` accepts a saved object without `commentary` (written that way, tested).
7. React lint: the effect in `useCommentary.ts` calls `setState` (same pattern as `useCountUp`); eslint passed.
8. Visuals: the chip tray, the commentary line and the start page were never looked at in a browser. Tailwind class names
   were copied from neighbouring code.
9. Hinglish lines were written by me and read by nobody else: tone and spelling need the owner's eye.

## Decisions and surprises
- **`scripts/start` order now:** stage `preflight` (before the preflight script, so a restart shows it), preflight,
  `.env` and folders, ports, stage `building`, `docker compose up -d proxy`, the unchanged "restart the proxy when
  docker/Caddyfile is newer than it" rule (kept word for word, now right after the proxy starts), open the browser once
  (not when `/` already answers 200, not with `QUEST_NO_OPEN` or `CI` set), `docker compose build`, stage `starting`,
  `docker compose up -d`, the unchanged health waits, stage `ready` (or `starting` with a "taking longer" note when the 90 s
  wait ends), `STAGE_DONE=1`. An `EXIT` trap writes `failed` (with `failedAt`) when the script ends before that. Every
  write to the stage file ignores its own errors; the file is replaced through a temp file and `mv`.
- The stage file lives at `<logs>/start/stage.json`, where `<logs>` is `./logs` or, for an isolated check project,
  `QUEST_CHECK_LOGS` from the env file named by `ENV_FILE` (the same variable `scripts/preflight.sh` reads; unset means `.env`,
  as before). Shape: `stage`, `startedAt`, `stageStartedAt`, `updatedAt` (epoch seconds), `detail`, and `failedAt` on failure.
- **502 is kept** (`P0-02.sh` accepts 502, 503 or 200 on `/` and on `/app/ping`; `/app/*` and every engine path stay bare
  errors). `F-15.sh` waits for 200 on `/`, unaffected. Other checks that mount `docker/Caddyfile` through their own
  override (`E-01`, `E-02`, `E-03`, `E-04`) get the new `/srv/starting` mount from the base compose file.
- **`/api/chapters` now carries `choices`** on the eight chapters' player messages (optional field, ignored by older code;
  `ui/src/types.ts` `ThreadMessage` has no `choices`, which I may not edit, so the thread uses its own
  `ChoiceMessage = ThreadMessage & { choices? }` from `ui/src/thread/logic.ts`). The Welcome scene (F-18) has its own chat and
  ignores choices.
- Commentary default is `hinglish` (on), not off: it is flavour under plain text and one palette item turns it off.
  Rotation starts at a random offset per language and moment, then never repeats a line until all are used.
- The first choice must equal the message text (schema rule, not only a convention): it keeps `text` the canonical line for
  every content check and for skip.
- Lines with an emoji got no choices, because the existing line is repeated as the first choice and C4b / the tone guide cap
  emoji per thread on the raw file.
- Replay of a thread reuses the remembered picks (it does not ask again) unless nothing was picked.
- Surprise: `handle_errors` cannot use a CEL status matcher safely without running Caddy, so the start page is gated by path
  only, not by status. Any error that reaches `handle_errors` on a page path (502, 503, 504) gets the page with its own code.
- Surprise: `useShellEffects.ts` calls `describeEvent` and `describeDanger` from `eventToasts.ts` and ignores `ToastSpec`
  fields it does not know, so the commentary rides in `description` (plain note first, a space, then the line).
