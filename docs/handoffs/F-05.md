# F-05 handoff: show_me carries its keys

## Schema change
- `packages/shared/src/levels/schema.ts`: `show_me` is now `string | { component, keys: string[] = [], title? }` (strict object, component id regex unchanged). A zod `transform` normalises both forms to `ShowMe { component, keys, title? }`, so `LoadedLevel.level.show_me` and `LevelFile` are always the object (`keys: []` for the string form). New exported type `ShowMe`. New tests: `packages/shared/src/levels/__tests__/show-me.test.ts` (normalisation, strictness, templates render inside keys).
- `levels/README.md`: example, field table and a short `show_me` paragraph updated.
- UI: `ui/src/types.ts` (`ShowMeSpec`, `Level.showMe: ShowMeSpec | null`), `ui/src/showme/index.tsx` (`defaultKey()` table deleted; `ShowMe({ spec, playerId })` renders the component once per key, wrapped in `data-testid="showme-panel" data-key=<key>`; `title` rendered if present; no keys and not `cache_stats` falls back to the existing "which key?" box), `Built.tsx`, `Level.tsx`, `ui/test/showme.test.tsx`, `ui/e2e/chapter0.e2e.ts` (new assertion: level 0.3's passed panel has `data-key="game:player:<id>"` and the card shows that key).

## ENGINE CHANGE NEEDED (not made, per spec)
`GET /api/levels/:id` returns `showMe` as the object but with keys UNRENDERED (`"game:player:{{player.id}}"`; the check script prints this). `engine/src/levels.ts` `renderLevel` renders only title, story, teach, task, brainstorm, hints and verify; `showMe: lv.show_me ?? null` is passed through raw. Suggested fix: add `show_me: lv.show_me ?? null` to the object given to `renderTemplates` and return `r.show_me`. Until then the UI substitutes `{{player.id}}` itself (`renderKey` in `ui/src/showme/index.tsx`, unit-tested); already rendered keys pass through, so the UI keeps working after the engine fix. Other template variables in keys would not be filled in by the UI.
