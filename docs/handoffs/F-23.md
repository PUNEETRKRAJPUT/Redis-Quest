### Hands-on panels (six, via `interactive`)
string (edit value: `SET`), hash (click a value to edit, or add a field: `HSET`), list (`LPUSH`, `RPUSH`, `LPOP`, `RPOP`), set (`SADD`, per-chip `SREM`), leaderboard (+/- per member and a new-member box: `ZINCRBY`, step 1/5/10), time to live (presets, slider, `EXPIRE`, `PERSIST`; an expired key offers `SET ... EX 60` to bring it back). The other thirteen only read and say so, pointing at the terminal.
Every gesture sends one string through `api.cli` and shows it as "ran: <command>" with the reply and a plain-words note; while a field is being filled the same line shows "will run: ..." so the player sees the command before sending. Keys under `game:` are never written: the panel reads them and shows a lock note; `runCommand` also refuses (tested, zero requests). Errors (WRONGTYPE, not a number, engine down) show inline in the ran line, never break the panel.

### Change visibility
Rows, chips, list items, stream entries, hash fields, facts, streak cells, board rows flash amber when new or changed; numbers (hits, misses, keys, visitors, scores, list length, streak, TS samples, docs) count to the new value; new geo points ping. Under reduced motion the flash shortens to 150ms and counting is instant.

### The nets (`/showme`)
Before the practice keys exist: all nineteen sample panels, light says "sample", controls inert with "Set up the nets, then touch the panel". "Set up the nets" runs ~35 commands (all `practice:*`, nothing on page load, nothing from effects); then every panel is live and the six are hands-on. "Reset the nets" re-creates, "Clean up" deletes (one `DEL` of the fixed key list plus `FT.DROPINDEX practice:idx`; no `KEYS`, which the engine flags as dangerous). `stats_latency_panel` stays a sample (a practice key cannot make route traffic). `grep -rn "practice:" levels` is empty, so the prefix is free.
