## Decisions and surprises
- `splitArgs` (engine/src/cli.ts) and the check evaluation (engine/src/verify/reply.ts, assert.ts) are copied into
  shared (`league/split.ts`, `league/evaluate.ts`) because the shared package cannot import the engine and the
  contributor script runs without the engine. Parity is pinned by tests: `split.test.ts` repeats the engine's cases;
  `engine/test/league-parity.test.ts` (to come) runs both evaluators over one table.
- Scoring database is 7 (`LEAGUE_DB`): the game's `game:*` keys are in 0 and no level selects another database.
  `scoreEntry` first runs `CLIENT INFO` and refuses unless it reports `db=7`, never flushes before that.
- Beyond the spec's refused list, entries may not use SELECT, MOVE, SWAPDB, FLUSHDB, RESET, HELLO, AUTH, CLIENT, COPY ... DB,
  MIGRATE, transactions, blocking commands and a few server-wide commands: any of them could leave the scratch
  database and write into the player's data, or never return.
- Shared's `loader.ts` keeps its zod-issue-to-error conversion private, so `league/loader.ts` has a small own version
  (unknown key, required, message). If a later task exports `zodErrors` from the levels loader, switch to it.
