## Decisions and surprises
- **`incidents/` is not in the image.** `docker/node.Dockerfile` copies only `levels` and `scenarios`. It needs `COPY incidents incidents` next to those two lines. I do not own that file. Until then `GET /api/matchday` answers with `deckErrors` and `canStart.ok=false`, and `POST /api/matchday/start` answers 503 `deck_unavailable`. `INCIDENTS_DIR` overrides the folder.
- **No refusal can be decided by the feature alone.** The verifier's guard lives inside `buildServer`, out of reach of a feature. The runner therefore starts every over through `POST /api/load/start` (in process, Fastify inject): that route takes the guard and answers 409 `verify_in_progress` while a level check or a traffic run is going. Over 1 never has a card, so the start request asks for its traffic before anything is changed: a refused start has changed nothing. Between overs the guard is free for a moment; if something else takes it, the runner retries for a few seconds and then ends the match with an error (everything is undone).
- **Cards never touch `game:*`.** The schema, the engine (`prefixProblem`) and the delete loop (key filter) all refuse it. `delete_keys` prefixes must start with `cache:`: only caches the player's code rebuilds can be deleted. The deleted keys are not put back.
- **maxmemory card only under `noeviction`.** Any other policy could evict keys that are not caches (`game:*` among them), so the card is skipped and the war room says so. The old value is journaled in `matchday-undo.json` (progress folder) before it is lowered, restored after the over, at the end of the match, before the next match starts, and when the engine next connects to Redis.
- **Single-node target only.** Sentinel and cluster targets are refused (409 `single_node_only`).
- **Seed = the UTC date as YYYYMMDD.** Two players in different time zones can be a day apart for a few hours. Other seeds: any whole number from 1 to 2147483647.
- **Which incident comes is hidden until it is played.** The overview shows which overs have an incident, not which card.
- **Three wickets and the innings is over** (all out); at most one wicket per over, six overs. 36 runs per over at 100% answered.
- The UI does not depend on `@quest/shared`, so the scorecard text is built by the engine and sent with the result (`result.text`).
- Extra route beyond the spec: `POST /api/matchday/stop`.
