## Gaps
1. **1.16 works-but-wrong not expressible.** "Three separate commands without multi()" produces the same Redis state as the multi version, and Redis does not roll back after EXEC, so no behavior assertion or side effect can tell them apart (no hook for round trips or atomic visibility, and `INFO commandstats` would be polluted by the engine's own MULTIs). I left it out: 1.16 has no antipattern verifier and no works_but_wrong solution. Needs a verifier primitive such as "commands issued by this call" to express.
2. **1.15 reference cannot be a pure `.redis` file.** The restore is a game action (`POST /api/progress/restore`), so the reference is FLUSHALL, DBSIZE, KEYS plus a comment. P0-09's CI must perform the restore (or fake the event) after running it.
3. **Answer, quiz and event verifiers in cli levels (1.4, 1.8, 1.10, 1.11, 1.15) have no way to carry the learner's typed answer or choice in a `.redis` reference.** Same shape as C0 level 3. Wrong solutions in 1.4 pass every `redis` check on purpose and rely on the missing answer or quiz to fail.
4. **Spec said `h-c-02-1` for 1.7**; the story uses Savitribai Bhawan (girls' hostel per hostels.json) and puts only seed users u-000002, u-000003, u-000010 on the board. The learner's own profile (1.3) uses their real hostel `h-c-02-2`. Not mentioned: Bunty, to avoid placing him in a girls' hostel.
5. Keys not in the spec's list, introduced by me: `lobby:m-041`, `lobby:m-042`, `lobby:m-999` (1.8), `ch1:users`, `ch1:seen:m-042`, `ch1:before-flush` (setup markers), `visitors:match:all-live`, `users:registered` (1.16).
6. 1.12 writes `match:m-041:balls` as the spec says; setup DELs it. If the app's bots later write that key during Chapter 4, nothing here collides, but a reviewer may want a different key.
7. `{{env.HOME_HOSTEL}}` from the spec's 1.7 note is not used.
