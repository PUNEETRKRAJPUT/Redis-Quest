  `$GITHUB_STEP_SUMMARY`, prints the last 400 stack-log lines on any failure, and stops the stack on exit.
- `scripts/review-pr <n> [--comment] [--i-read-the-diff] [--keep]`: fetches the PR into `refs/review-pr/*` and a temp
  worktree; refuses (exit 2) when a changed file is `scripts/*`, `.github/*`, `docker-compose.*`, `docker/*`, any
  `package.json`, `pnpm-lock.yaml`, `pnpm-workspace.yaml`, `.npmrc`, `.node-version`, `.env.example` or any `*.sh`,

- That `pnpm --filter '@quest/engine...' --filter '@quest/app...' --filter '@quest/runner...' build` builds shared first

- That the engine, app and runner start from `engine/dist/main.js`, `app/dist/main.js`, `runner/dist/main.js` with
  only the environment `stack.mjs` gives them (read from `engine/src/config.ts`, `engine/src/verify/config.ts`,
  `app/src/config.ts`, `runner/src/config.ts`, `docker-compose.yml`). The app and runner entry files only start their
  server when `PORT` is set; `stack.mjs` always sets it.
- That the engine needs nothing from a ui build (`ui/dist` absent: `server.ts` skips the static plugin) and nothing
  else under the hostnames `proxy`, `engine`, `app`, `runner` than `APP_URL` and `RUNNER_URL` (a grep found none).
- That a bare `redis:8` service container accepts the five `CONFIG SET` calls (maxmemory, policy, save, appendonly,
  appendfsync). A failure is logged and ignored.
- That the cli, code and decision levels grade green on a 2 vCPU amd64 runner with a bare `redis:8` and a service
  `postgres:16`. The first run may show real MISMATCH rows that are environment, not content (for example a level that
  reads a Redis setting the compose Redis has and this one lacks, a `COMMAND DOCS` difference, or a code level that
  is slower than its timeout). If so, either fix the stack (`stack.mjs`) or add the level to the skip rule with a reason.
- That `curl`, `psql`, `pg_isready`, `gunzip`, `sed`, `tee` and background jobs behave as in `ci.yml` on `ubuntu-latest`.
- That a background process started in the "Start the stack and grade the levels" step is still alive when that same
  step uses it (it is one step on purpose).
- `scripts/review-pr`: `gh pr view --json ... --jq`, `git fetch <remote> +pull/N/head:refs/review-pr/head-N` and
  `git worktree add --detach` behave as on a normal clone whose remote `origin` is the public repo (override with
  `REVIEW_PR_REMOTE`). G-01 run from a temp worktree runs its own `pnpm install --frozen-lockfile` there.
- That the grader, which unlocks levels with `POST /api/levels/:id/complete`, is fine with a fresh Redis that has no
  `game:*` keys beyond what the engine creates.

## Decisions and surprises
- Deterministic mode skips every level with a traffic verifier, not only latency or baseline ones. Even the count
  assertions (`db_queries_lte`, `hit_ratio_gte`, `error_rate_lte`) depend on how much load a 2 vCPU runner can generate
  in the run window. One function (`scripts/ci/deterministic.mjs`) to loosen later.
- Random interview pool levels (finale) are skipped: the draw can land on a traffic level.
- The skip helper lives in `scripts/ci/` (a folder this task owns) rather than `scripts/grade/`, which D-01 owns only
  through `grade.mjs`.
- `stack.mjs` applies the compose Redis settings with a raw RESP socket because a CI `redis:8` starts bare and the
  grader resets exactly those settings after `CONFIG SET` levels. It avoids importing the `redis` package (no new
  dependency, no module-resolution questions for a script in `scripts/`).
- `review-pr` refuses a wider list than the spec's `scripts/` and `.github/`: `docker-compose.*`, `docker/`, every
  `package.json`, the lockfile, `.npmrc`, `.env.example` and any `*.sh` also run or steer code on the Mac (lifecycle
  scripts, the compose file G-01 builds, ops solutions that `G01_RUN_OPS=1` executes). Easy to narrow in `is_sensitive`.
- `review-pr` runs G-01 only when G-03 passes: G-03 is the tripwire for a check that would act on the default project.
- `review-pr` also refuses to start when containers of `quest-g01` exist, because G-01's project name and ports are
  fixed and its own cleanup would remove another run's stack.
- G-01 does not use `scripts/check/lib/isolate.sh`; it scopes every call with `-p quest-g01` (G-03 accepts that), so
  `review-pr` inherits that isolation rather than adding its own project name.
- The first real run of `pr-verdict` is this branch's own pull request. The job builds without the ui, so it will not
  prove `next build`; `ci.yml` does that.
- `SECURITY.md` invents no contact address: it points at GitHub's private "Report a vulnerability" button if enabled,
  else a content-free public issue. The checklist below enables the button.
- Prettier ignores `*.md`, `*.yml` and `.github/`, so those files are not format-checked by CI.
