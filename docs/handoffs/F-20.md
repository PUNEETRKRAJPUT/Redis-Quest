### New optional props (callers passing only `messages` and `label` get the new look and sensible defaults)
`title` (default "Chapter thread"), `animate` ('auto' | 'always' | 'never', default 'auto': arrives on first view, fully revealed after), `maxRevealMs` (default 8000), `maxHeight` (CSS length or px, or 'fill' to fill the parent height; default min(58vh, 32rem)), `onRevealed`, `rememberSeen` (default true), `className`.

### Behaviour
- Messages grouped by sender (one avatar and name per run, joined corners); the player's side ("you") is right-aligned in a flood tint with blue read ticks and no avatar. Avatar colour: the five cast get fixed distinct brief tokens, anyone else hashes into the same five.
- Arrival: quiet gap, typing dots (delay grows with length, capped; bursts from one sender are faster), message lands, `msg` cue (sound setting respected, max one per 140 ms). Total capped at 8 s by scaling every step, however long the thread. Typing dots are skipped when a step scales under 110 ms.
- Auto-scroll follows only while the player is at the bottom of the thread's own scroll area (never `scrollIntoView`, never the page). Scrolling up shows a "N new messages" pill. A thread that opens already revealed starts at its first message.
- Show all button (same element becomes Replay, so keyboard focus survives) and Escape (document listener only while an arrival is running; never swallows the key). Seen = fully revealed once; stored per content hash. Replay is hidden under reduced motion (nothing to replay).
- Reduced motion (setting or OS): everything at once, no typing indicator, no Replay. Arrival waits until the thread is actually on screen (closed `<details>`, below the fold).
- A11y: `ol` labelled by `label`, `aria-live="polite"`, `aria-relevant="additions"`; each message has sr-only "Name at HH:MM:" and the visible name, time and ticks are aria-hidden; typing indicator is aria-hidden; no focus traps.

## What the integration task must know
- **CSS modules do not work in this app.** `next.config.ts` sends every `*.css` through the Tailwind Turbopack loader (`as: '*.css'`), so a `.module.css` becomes global CSS and `styles.foo` is `undefined` (I hit this: classes silently missing). The shared rules and F-16 cookbook say to use a CSS module for component CSS; that advice is currently wrong. I used Tailwind utilities with arbitrary values only.
- **Legacy hooks kept on purpose.** `ui/e2e/chapter0.e2e.ts` finds messages with `.thread .msg`, so the `ol` keeps class `thread` and each `li` keeps `msg`. The legacy unlayered `.thread`/`.msg` rules in `styles.css` beat layered utilities, so the markup carries important utilities (`p-0!`, `border-0!` ...) to neutralise them. When the legacy stylesheet is deleted those are harmless; the e2e selector can then move to `[data-testid=thread-msg]`. No test or e2e file was changed.
- Callers found: `ui/src/screens/Level.tsx` (inside a `<details open>`) and `ui/src/map/FixtureDetail.tsx` (F-19). Both pass only `messages` and `label`. The thread has `my-3` and `max-w-[34rem]`; a caller wanting a different width can wrap it. The Level screen shows the thread above the story text; with the default arrival it plays on first view of a level, and only when its `<details>` is open and on screen.
- `Welcome.tsx` (F-18) holds its own `ThreadMessage[]` state; it does not use `Thread` today.
- E2E note: the first message now appears after about 0.3 s (typing), Playwright's `toBeVisible` waits for it. A caller needing instant text can pass `animate="never"`.
- Not done, by design: no fake composer bar (it would look usable and is not).
