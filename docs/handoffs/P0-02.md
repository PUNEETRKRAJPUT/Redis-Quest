## What I did
- `docker/node.Dockerfile`: multi-stage on `node:22-bookworm-slim`. Stage `build`: corepack, manifests-first
  `pnpm install --frozen-lockfile`, `pnpm -r build`. Stage `runtime`: `pnpm install --prod --filter '!@quest/ui'`,
  copies each package's `dist/` plus `ui/dist`, `levels/`, `scenarios/`; `USER node` (uid 1000), `WORKDIR /srv`.

  Proxy has no `depends_on`. Verified every profile service starts (sentinels, replica, nopersist, six cluster nodes).
- `docker/Caddyfile`, `docker/sentinel/sentinel.conf`, `docker/README.md`, `.env.example` (6379 default).
- `scripts/preflight.sh`, `scripts/start`, `scripts/stop`, `scripts/reset`, `scripts/check/P0-02.sh`.

## Beginners and Docker Desktop settings
- Docker Desktop default memory limit is often 50% of RAM or less; on a 16 GB Mac that is about 8 GB, fine, but if someone
  lowered it, preflight prints: Docker Desktop > Settings > Resources > Memory limit, set 8 GB, Apply & restart.
- Docker Desktop must be running (whale icon steady). Preflight offers `open -a Docker` only on an interactive terminal.
- Host `/Users` file sharing must be enabled (default on). Bind mounts `./logs`, `./.progress`, `./workspace` rely on it.
- Disk: Docker Desktop's virtual disk limit is under Settings > Resources > Virtual disk limit; images need about 2 GB.
- Starting Docker Desktop on this Mac also restarted the user's other containers (agent-marketplace-*, port 3000 and 5432,
  am-*); they crashed again within seconds and were not running when I finished. I did not touch them. A future run with them
  up will make preflight FAIL on 3000/5432 and name the container.

## What surprised me
- `.dockerignore` is not in "Files owned", but without it the host's macOS `node_modules` (pnpm symlinks) would be copied in.
  I used the BuildKit per-Dockerfile ignore file `docker/node.Dockerfile.dockerignore` (inside owned `docker/`). It works
  with `docker compose build`. Orchestrator: say if you would rather have a root `.dockerignore`.
- `scripts/start` and the check create `postgres/init/` (empty dir, not tracked by git) so Docker does not create it
  root-owned on the host. P0-04 fills it. Same for `logs`, `.progress`, `workspace`.
- Redis 8.10.3 ships a fifth module, `vectorset`, in MODULE LIST. Not used anywhere (no vector content in this project).
- Preflight accepts overrides from the process environment before `.env` (same precedence as compose).

## What wave 3 must know
- Image: `redis-quest-node:latest`, runtime has production deps only (no typescript/vitest), non-root uid 1000, `/srv` is cwd.
  Layout inside: `/srv/{engine,app,runner}/dist`, `/srv/packages/shared/dist`, `/srv/ui/dist` (serve statically from the engine),
  `/srv/levels`, `/srv/scenarios`. Level/scenario edits require a rebuild (they are baked in, not mounted). Tell me or change the
  compose volumes if you want them mounted instead.
- New dependencies: add to the package's `package.json` and `pnpm-lock.yaml`; the build uses `--frozen-lockfile`. Native
  modules needing install scripts need `pnpm.onlyBuiltDependencies` in root `package.json` (pnpm 10 skips build scripts).
- Env set by compose: REDIS_URL, DATABASE_URL, LOG_DIR=/logs, PROGRESS_DIR=/progress, WORKSPACE_DIR=/workspace, APP_URL=http://proxy:3000/app,
  RUNNER_URL=http://runner:4100, ENGINE_URL=http://engine:4200, PORT (engine 4200, app 4000, runner 4100). Listen on 0.0.0.0.
- Caddy keeps the `/app` prefix, so the app must mount its routes under `/app`. Caddy answers 502 until engine/app resolve.
  `GET /health` on the engine is what `scripts/start` polls through the proxy.
- Bind-mounted dirs on macOS are owned by the host user via virtiofs; the container user is uid 1000 and could write them here.
- The host Redis port is `REDIS_PORT` (6390 locally); inside the network it is always `redis:6379`.
- Compose command syntax for profiles: `docker compose --profile cluster up -d redis-c1 ...` (verified they start).
