## How "taught" is decided (so a later session can compare it with a real Redis)
A command is taught when, for any campaign level or community level the engine loaded:
1. its **reference solution** runs it: a `.redis` line (first word), a `.sh` line (the word after `redis-cli` and its
   flags), or a `.js` solution calling it on the learner's `redis` client (`redis.zIncrBy` is `zincrby`; a method
   name that is not itself a command credits the longest command that prefixes it, so `xGroupCreate` credits
   `xgroup` and `zRangeWithScores` credits `zrange`; the whole `redis.multi().a().b().exec()` chain; a client made
   with `redis.duplicate()`; `sendCommand(['XADD', ...])`; `redis.call('GET', ...)` inside a Lua string), or
2. a **check** of the level runs it: `redis` and `antipattern` checks, a behavior `sideEffect`, and the command an
   `answer` verifier reads its expected value with.
Not counted: setup steps, the known-wrong solutions, decision levels' option ids, prose, `quiz` verifiers.
The board is top-level only: `XGROUP CREATE` counts for `xgroup`, and subcommand names (`client|list`) are not rows.
Left out as the terminal does (F-22): names with a dot, upper case or a leading underscore, and docs `group: module`.
Every response carries `listed` (the server's `COMMAND LIST` length) and `skipped.{subcommands,modules}` so that
`listed = commands + skipped.subcommands + skipped.modules` can be checked against `redis-cli COMMAND LIST | wc -l`
(E-06 measured 669 on redis:8).

**Number I expect:** 97 level files are read (96 campaign + the house community level). Running the same code over
them offline (a throwaway script, with a permissive command set because there is no Redis here) found about 68
distinct in-scope commands taught; expect `taught` between 65 and 72 on a real Redis, out of a few hundred
(`commands`). The exact number depends on the server's command list (the `.js` method-to-command mapping needs it).
