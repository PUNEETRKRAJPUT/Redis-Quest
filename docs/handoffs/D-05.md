## Route and event shapes (stable; D-06 builds on these)

All under `/api`. Errors are `{ error, message }` like the rest of the engine.

`GET /api/community`
```
{ packs: [{ id, title|null, incident: [{from,time,text}], brokenFiles: string[], errors: string[],
            levels: [{ id, title, mode: 'cli'|'decision', number, author: {name, github?}|null,
                       status: 'new'|'in_progress'|'passed', attempts }] }],
  levelCount, errorCount }
```
A pack with errors is still listed (its good levels too); `errors` are `file:line:col path: message` lines.
The folder is re-read on every call (at most once a second), so dropped-in files appear without a restart.

`POST /api/studio/validate` body: the draft (`StudioDraft`, packages/shared/src/levels/draft.ts) or `{ draft }`.
```
200 { ok, id|null, directory|null, files: [{path, content}], problems: [{path,message}],
      errors: [{ file, line, col, path, message, text }] }
```
`problems` are about the draft's shape (path into the draft, `checks[1].key`); `errors` are the real loader's, with
`file` as the repository path (`levels/community/<pack>/01-x.yaml`), positioned in the YAML in `files`.
400 `invalid_draft` when the body is not an object.

`POST /api/studio/playtest` same body.
```
200 { passed, refused: string|null, keys: string[],
      runs: [{ name: 'reference'|<solution path or option id>, expect: 'right'|'wrong'|'works_but_wrong',
               because?, verdict, ok, transcript: [{line,reply,type,ms}], outcome: VerifyOutcome }],
      validation: <the validate response> }
```
`refused` is set (and `runs` is empty) when nothing ran: the draft does not validate, names a `game:*` key or a
command that changes the server, or would write a key that already exists in the player's Redis (the message says
which). `passed` means the reference is `right` and every known-wrong solution gave its declared verdict. `outcome.checks`
are the same `CheckResult` list `POST /api/levels/:id/verify` returns. 503 `redis_unavailable`, 409 `playtest_in_progress`.
Keys the draft wrote are removed again (UNLINK) after the runs, also when a run throws.

Level event, on the engine bus, when `passed` is true:
`bus.emit('level.event', { kind: 'custom', name: 'studio_playtest_passed', data: { levelId, pack, mode, runs } })`.
It is also in `GET /api/events` and on the WebSocket, like every level event.

Playing a community level (same payload shapes as the campaign's, no XP, never locked, own progress file
`<progressDir>/community-progress.json`): `GET /api/community/levels/:id` (the `LevelData` shape plus
`community: { pack, author }`, `slots: {own: [], active: false}`, `interview: null`), `POST .../start`, `POST
.../brainstorm`, `POST .../hint`, `POST .../verify` (`{ answers }`; returns the verify outcome plus `attempts`,
`status`, and `ideal` once allowed), `GET .../ideal`.

## Decisions and surprises
- **Second service, not a flagged extra of LevelService.** `LevelService.orderedIds` drives progress.json, XP, locking
  and the 96-level count, and the campaign routes in `server.ts` (read-only for this task) call `levels.get(id)` and
  then pay XP and require a progress entry. A community level therefore lives in `CommunityService`, is played through
  `/api/community/levels/:id/*` in `features/studio.ts` and has its own small progress file.
- **Community rules** (`community.ts`): modes cli and decision only; verifier types redis, antipattern (checks), quiz,
  answer only, all read-only; setup only Redis commands, none of the server-changing ones; no `game:*` anywhere; author
  required; no interview; a pack named like a campaign chapter is refused. Every level carries `reward.xp` because the
  schema requires it, but nothing awards it.
- **The validator is the loader.** A draft compiles to files, is written to a scratch directory, loaded with
  `loadCommunityPack`, and the directory is removed, so every error is the validator's own.
- The play-test also runs each known-wrong solution (what CI does), not only the reference.
