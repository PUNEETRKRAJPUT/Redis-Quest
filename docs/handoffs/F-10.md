# F-10 handoff: stats_latency_panel and otp_limiter_panel

## What each component shows and reads
- `stats_latency_panel` (`StatsLatencyView` in `ui/src/showme/views.tsx`, wrapper `StatsLatency` in `index.tsx`): p99 sparkline (reuses the Metrics panel's `Sparkline`), current p50, p99, requests/s and Postgres queries/s for the route `GET /app/players/:id/stats`, the caption "the page is slow because every request asks Postgres", and `show_me.keys` listed beneath with `EXISTS` (polled every 2 s) as "does not exist yet" or "cached". Reads: the store's `metrics.tick` history (per-route `p50Ms`, `p99Ms`, `count`, `dbQueries` for that route), `GET /api/metrics?seconds=60` every 2 s as a fallback for p50/p99 when the route has no tick yet, and `POST /api/cli` EXISTS for the keys. Rendered once per level (keys inside the panel, so level 2.1's `keys: []` works). No data shows "no data" / "not reported".
- `otp_limiter_panel` (`OtpLimiterView`, wrapper `OtpLimiter`): per key, `TYPE` then `HGETALL` (token bucket fields), `GET` + `TTL` (fixed window count and reset), or `ZCARD` (sorted-set log member count), through `useRedis` every 1 s; missing key shows an empty state. Below: requests served on `GET /app/limits/ping` from `GET /api/metrics` (`routes[...].count`, 60 s window).
- Both are registered in `SHOW_ME_IDS` (now 14), added to `#/showme` with sample data (`SAMPLE.stats`, `SAMPLE.limiter`), and use the existing `.showme`, `.facts`, `.kv-table`, `.stream` classes, so light and dark follow the other components. No CSS added.

## Finding the spec could not fully meet
The "denied (429)" tally cannot be shown. The app's recorder counts `errors` only for status >= 500 (`app/src/metrics.ts`), so 429s from `/app/limits/ping` are not in the engine metrics. The panel shows the request count and "denied (429): not reported". Not verified live: no Chapter 3 level exists in the check's scratch levels, so the live wrappers were exercised only through unit tests of the views and `routeTickSeries`; the gallery uses sample data.
